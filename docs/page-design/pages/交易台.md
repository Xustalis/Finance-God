# 交易台 `/desk`

> 版式与视觉以当前实现为准：`TradingDeskView.vue`、`components/desk/*`、`styles.css` 交易台段。
> 全局令牌与壳层约束见 `01_前端统一设计规范.md`。

## 目标

一个已认证的桌面交易工作区：左侧完成行情、持仓、自选和模拟交易，右侧保留与当前对象同步的 Agent。顶部使用 `FINANCE GOD` 字标与「金融教父 · 投研与决策档案」副标；提醒、钱包、交易记录、画像和设置不进入 Agent 能力。

## 工作区合同

| 工作区 | 服务端事实 | 用户操作 | 空/失败状态 | 版式组件 |
|---|---|---|---|---|
| 总览 | `/market/overview`、融资余额事实、披露事实、`/market/news` | 选标的、刷新 | 显示市场时段、上游时间/频率/freshness/最后成功读取时间；休市时展示最近已发布交易日。批量行情按标的隔离失败，保留成功标的并显示失败标的原因；行情禁止 mock。公开资讯 crawler 失败时显示 error 或明确 stale 的上次真实结果 | `OverviewWorkspace`：行情图表 + 事实列表 + 公开资讯列表 |
| 持仓 | `/simulation/accounts/current`、`/simulation/portfolio` | 点击标的进入对应交易工作区；“卖出”进入交易区并预填可卖数量 | 账户明确不存在时才显示建立操作；读取失败时暂停建账；无实时行情时市值和浮盈为「行情不可用」；可卖数量为零时只禁用卖出，不禁用标的导航；正式页面不提供历史演示入口 | `PortfolioWorkspace`：`.market-sheet` + `.market-table` |
| 自选 | `/workspace/watchlists`、`/workspace/candidates` | 新建/改名/删除分组，增删标的，忽略候选；AI 可在明确指令下加入当前分组 | 修订冲突要求刷新；候选只包含具备真实 PandaData 快照和上游时间的标的，不能下单；全量行情失败明确不可用 | `WatchlistWorkspace` |
| 交易 | `/market/overview`、统一 K 线接口、`/simulation/market-orders`、`/simulation/fills` | 选择交易股票、查看该标的实时 K 线，输入买卖方向和数量，一次点击完成模拟市价成交 | K 线与引用价必须匹配当前交易股票，展示上游时间/频率/freshness；切换标的时不保留旧图冒充新数据；服务端重新绑定可信行情并校验现金或可卖持仓；失败不生成订单或成交 | `TradingWorkspace`：复用 `MarketChart` + 行情带 + 极简表单 + 成交回执 + 最近成交 |
| 复盘 | `/trade-episodes`、案例 decisions/review、`/agent-learning/summary` | 选择案例、查看决策时间线、重试失败复盘、刷新自学习摘要 | 主观信息缺失显示“当时未记录”；持仓未归零不伪造终局复盘；学习 Worker 未运行、陈旧或损坏独立显示且不影响交易案例 | `ReviewWorkspace`：紧凑表格 + 自学习规则线分区 + 决策时间线 |
| 我的 | 模拟账户/订单/成交、本人画像与设置 | 刷新模拟事实、保存本人设置 | 每类失败独立呈现 | `MyPanel` 浮层分页 |

## 联动规则

1. 切换工作区和标的递增 `contextVersion`，先通过轻量 bootstrap 同步服务端上下文；bootstrap 成功后页面立即进入 ready，再通过 `/desk/quick-commands` 按新上下文异步生成三条不同角度的快捷指令。生成加载或失败不阻断自由输入，失败明确显示且不使用固定模板；内部 context 标识不在 Agent 标题栏展示。
   直接回答完成后按 `decision_id` 生成承接答案的三条建议；工作流完成后按本人
   `run_id` 与正式 Evidence 生成下一步建议。“换一组”复用当前阶段，活动 Run
   期间禁用；客户端以 `context_version` 丢弃跨工作区或跨标的的迟到响应。
2. Agent 控制左侧只通过 bootstrap 下发的版本化语义动作目录；支持切换工作区、选择标的、刷新行情、设置筛选/排序、打开记录、定位研究候选、预填未提交交易草稿，以及打开工作流产物、提醒和交易计划。客户端在应用前精确比对当前 `context_version`，服务端校验动作参数并拒绝 DOM、坐标与 CSS 选择器；回执仅为 `applied`、`rejected` 或 `stale_context`。
3. 行情缓存统一收集总览、持仓和自选标的；仅这一处轮询，页面隐藏时暂停，恢复立即刷新。
4. Agent 通过 `/agent/desk/decision/stream` 取得服务端 `answer | workflow` 判断及可选 `ui_actions`，不在提交前额外渲染上下文摘要。直接回答使用上游模型原生 delta 写入当前纸片，完成前显示轻淡入文字与生成光标；工作流分支继续返回普通 JSON。动作由模型从服务端目录提议，服务端按同一参数策略复核并绑定请求的 `context_version`；浏览器仅在流成功结束后并发提交动作给 `/desk/ui-actions`，只对 `applied` 回执调用前端执行器。问候、概念和功能问题由对话 Agent 直接回答；行情、研究、组合或交易计划等多阶段问题才通过 `/workflows/desk` 创建耐久工作流。正式 Run 执行期间输入保持可用，普通问答可并发且不得清除活动 Run；后续正式任务进入可折叠待办并在当前 Run 终态后顺序启动。浏览器不自行分类，也不用定时器拆分完整答案。
5. `queued/running/cancelling` 时保留当前 Run 并禁用新提交；Run ID 与用户意图写入 `sessionStorage`，刷新后恢复。任务卡状态来自持久化 execution audit，节点计数只来自已持久化产物。活动 Run 使用基于 revision 的单一长轮询；页面隐藏、切换 Run 或卸载时取消，恢复可见后立即读取并重新订阅。
6. 终态在同一线程显示：`completed` 展示结论、事实、推断、未知项和来源；其他终态显示服务端错误。失败不替换为默认答案。
7. `research_candidates` 完成后并行读取 `ResearchCandidateSet` Evidence 与
   `/workspace/candidates`，后者按同一画像投影重新计算并刷新自选区；浏览器不
   自行选股、排序或补全推荐。
8. Agent 始终展开；工作区标签保持固定顺序，不显示宽度、收起、排序或重置布局设置。
9. 提醒 Toast 的「隐藏」只改变本地可见性；只有提醒记录中的「标记已读」才调用已读接口。
   重大行情提醒由持仓、自选和最近一次服务端确认的当前标的映射，通过
   `/events` SSE 按用户游标推送。页面隐藏时断开，恢复后先补历史再重连；
   普通提醒可在 8 秒后隐藏，高优先级提醒保持可见，连接失败必须显示断开状态。
10. 订单错误与交易计划错误是两个独立状态；切换到自选时不得显示交易区撮合错误。
11. Bootstrap 使用显式 `loading | ready | error` 状态。浏览器按当前用户保存最近一次工作区与标的，仅用于首次 bootstrap 请求提示，避免先加载默认对象再重复同步；不缓存或恢复服务端上下文版本、能力、画像和动作目录。首次加载和上下文刷新时立即使旧 `context_version` 失效；只有当前工作区与标的的最新请求可回写。画像与能力在服务端并行装配，响应不包含快捷指令；成功后立即进入 ready 并独立加载初始快捷指令。加载中显示同步状态，失败显示服务端错误和重试入口，不得把正常等待描述为“不能创建任务”。
12. Agent 标题区提供“任务历史”。列表与详情在右栏原位切换，按服务端分页回看 Run 与正式报告；初始化从历史接口恢复唯一活动 Run，不以 sessionStorage 作为任务事实源。活动任务可取消，失败任务可按原输入重试；服务端确认可复用时可创建从失败节点继续的派生 Run。
13. 正式交易台不提供历史演示入口，也不读取历史模拟时钟来替换总览行情、现实资讯或研究候选。模拟账户、订单和成交仍是仿真业务数据，但其估值与交易引用价使用服务端实时市场合同。
   批量读取某一标的失败时不得清空其他标的的成功行情；服务端返回逐标的 warning，页面在保留成功数据的同时明确显示失败标的。
14. 交易区复用总览的 `MarketChart` 与统一 bars 状态。交易表单确认股票代码后同步当前 `symbol` 并加载对应行情/K 线；周期切换复用同一频率控制。标的或周期变化时清空旧 bars，迟到响应不得覆盖当前图表。
    分时、5 分、15 分和 1 小时读取服务端 1 分钟 bars；日线、周线和月线读取服务端日线 bars，禁止把单个交易日的分钟数据冒充长期日线。
   生产能力目录未启用指数分钟线，因此指数只开放日线、周线和月线；切换到指数时自动回到日线，禁用控件必须说明原因。
   从指数行情进入交易工作区时，当前标的切换为默认可交易 A 股个股；不得用指数快照创建模拟订单草稿。
   用户明确要求“制定交易策略并填写交易单”时，服务端先完成正式交易计划工作流；前端只从完成节点的版本化 `trade_plan` 读取唯一启用的市价动作并填写模拟表单。计划未确定数量时保持数量为空，多动作或限价动作明确提示不能自动映射。任何预填都不得自动提交订单。
15. 进入复盘工作区时并行读取交易案例与 Agent 自学习摘要。自学习摘要来自独立 Worker 的原子知识快照，只展示最近已验证结论；其失败状态与交易复盘错误隔离，不阻断案例选择或复盘重试。

## 总览信息层级

1. **大盘指数**：可点击行选择标的；列含最新价、涨跌、涨跌幅、上游时间与 freshness。
2. **市场情绪**：融资余额原始事实（最多展示若干条字段），不生成情绪分数；仅适用于 A 股个股。
3. **公司披露**：PandaData 公司披露原始事实，不生成新闻摘要；仅适用于 A 股个股。
4. **市场资讯**：服务端 crawler 抓取的综合公开财经资讯，展示来源、发布时间和安全原文链接；不伪装成当前标的专属事实。

首次进入总览可使用五分钟内的上次成功真实抓取；用户点击“刷新”时必须强制重新抓取最新资讯。刷新失败只显示错误或明确标记为 stale 的上次成功真实缓存，不允许历史演示或 mock 替代。

当前标的是指数时，两个个股事实区域显示适用范围，不发起事实请求，也不将能力不适用
降级为 mock。用户切换至 A 股个股后恢复读取对应标的的 PandaData 真实事实。

市场情绪、公司披露与市场资讯属于 `trade_eligible=false` 的参考模块。启用 mock 保底时，模块标题旁
必须显示「模拟数据」，并展示真实请求失败原因、mock 生成时间和重试入口；所有条目使用
Finance-God mock 来源标识。mock 内容不得参与 Agent、研究候选、提醒、交易或复盘证据。

| 宽度 | 行为 |
|---|---|
| ≥1024px | 左右等宽分栏；Agent 持续展开 |
| &lt;1024px | 同一路由上下排列；左栏在上、Agent 在下；顶栏数据态可压缩 |
| ≤680px | 字标副文案与部分顶栏文字可隐藏；行情表横向滚动；事实区单列 |

宽屏下工作区导航与历史演示时间条固定在左栏顶部，左侧内容区和右侧消息/任务历史区各自滚动；窄屏上下排列时恢复自然页面滚动，避免嵌套纵向滚动。

## 可访问性

- 语义：`nav`、`table`、`form`、`details`、`button`、`aria-live`（Agent 线程）
- 涨跌同时用 `.up`/`.down` 色与符号文本
- 浮层可关闭；交互控件可键盘操作
- 支持 `prefers-reduced-motion`

## 落地约束（与实现对齐）

- 行情 `last/change` 在适配层归一为数字；允许 `stale` + `released` 作为模拟草稿引用价（有有效最新价时）。
- 极简交易只支持模拟 A 股市价买卖；服务端再次读取 PandaData，原子创建订单、成交并更新账本。
- 用户点击“立即买入 / 立即卖出”即完成本次确认；Agent 只能预填，不可提交。
- 持仓行“卖出”只切换到交易区并预填标的、卖出方向与当前可卖数量，不得自动提交订单；交易区继续执行行情、账户与可卖数量校验。
- 余额、持仓或行情校验失败时不生成半成品订单；幂等键防止重复点击产生重复成交。
- 无画像时「我的」引导至 `/app/exe`，不伪造摘要。
- Agent 对 `queued` 明示可能等待执行器；`running` 按真实 Agent/服务节点展示等待、执行中、完成或失败；终态展示服务端证据或错误，不本地模拟进度。Run ID、revision 等技术元数据默认折叠。
- 正式任务作为 Agent 对话消息呈现；活动状态默认展开，在时间线中直接显示真实状态、节点与进度。摘要随服务端状态更新：`queued` 明示“正式任务已受理”，`running` 明示“正式任务已开始执行”；终态仍可展开回看。
- Agent 提交阶段只显示可证实的状态：「正在生成回复」「正在创建研究任务」「等待 Worker 领取」「正在执行节点」；不得展示浏览器推测的百分比或虚构阶段。
- 自选可申请服务端交易计划；计划展示在交易区，不自动下单。

- Agent 栏提供“语音通话”入口，通话状态在右栏原位呈现，左侧当前工作区不得卸载或遮挡。
- 用户开口可打断 AI 播报；完成字幕回写 Agent 时间线。
- 通话失败显示原因并保留文字输入，不改变工作流、UI action 或模拟交易权限。
# 持仓与卖出职责

- 持仓工作区只展示模拟账户、模拟仓位和真实行情估值，不提供自动卖出、止盈止损或保护策略入口。
- 买入与卖出统一在“交易”工作区完成；持仓页不创建订单或策略。
