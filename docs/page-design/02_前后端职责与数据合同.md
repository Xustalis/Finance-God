# 前后端职责与数据合同

## 1. C/S 职责

| 责任 | 客户端 | 服务端 |
|---|---|---|
| 行情展示 | 轮询、展示上游时间与 stale/error | PandaData 凭据、标准化、缓存、持久 observation、质量判断 |
| 画像 | 采集、展示最小投影 | 保存原始画像、生成脱敏投影、版本化与访问控制 |
| 研究候选 | 展示解释和下一步 | 使用画像投影、行情和规则生成可研究候选 |
| 工作流 | 发起、订阅状态、显示回执 | 创建、调度、执行、租约、审计、恢复、事件流 |
| Agent 自学习 | 在复盘区按需读取状态与已验证成果 | 独立 Worker 采集、推理、验证并原子写入知识快照；API 只读投影健康度和已验证结论 |
| Agent 控制左侧 | 执行语义回执、处理 stale context | 下发 `UiActionDescriptor` 白名单和审计回执 |
| 提醒 | Toast、记录、已读操作 | 规则评估、历史、Outbox、SSE、已读/处理状态 |
| 用户设置 | 表单和本人提交 | 账户设置持久化；严禁暴露给 Agent |

研究候选的唯一业务实现是服务端 `CandidateScoringService`。`GET /api/workspace/candidates`
与 `research_candidates` 工作流必须读取同一个 `SuitabilityProfileProjection`：
优先使用用户选定方向，否则使用画像推荐方向；再结合当前模拟持仓和 PandaData
行情生成五项独立解释。响应携带 `profile_version`、`directions`、`generated_at`、
规则版本、上游时间、反方证据和未知项。教育限制不阻断研究候选生成；无画像、无受支持方向或行情
不可用时返回明确的 `unavailable_reason`，不得回退为全市场默认推荐。
候选数组只包含已取得真实 PandaData 快照且保留上游时间的标的；部分标的行情失败时
排除失败标的，全部失败时返回 `MARKET_DATA_UNAVAILABLE`，不得把缺行情占位项作为
“可研究候选”返回。

## 2. 统一约定

- `/api/v1/*` 的认证/设置/画像使用 `{ success, data, error, meta }` 包络。
- `/api/*` 的交易域新接口也必须迁移到相同包络；历史裸 JSON 接口在适配层中兼容，不向页面组件泄露差异。
- Bearer Token 只由客户端认证层附加；PandaData 凭据永不下发浏览器。
- 所有写命令带 `Idempotency-Key`；所有可变上下文带 `context_version`；写回执包含 `applied | rejected | stale_context`。
- 时间使用 ISO-8601 UTC，展示层转为用户时区；金额和数量以字符串传输，避免浮点损失。

## 3. 交易台启动合同（P1）

`GET /api/desk/bootstrap`（Finance 裸 JSON，非 `{success,data}` 包络）

```json
{
  "owner_id": "user-1",
  "section": "information",
  "symbol": "000001.SZ",
  "context_version": "desk:user-1:information:000001.SZ:1721900000",
  "profile_projection": {
    "projection_version": "suitability-v1",
    "risk_level": "moderate",
    "completeness": 0.86,
    "available": true,
    "degraded": false
  },
  "ui_action_catalog": [
    { "id": "select_symbol", "object": "instrument", "mutation": "ui_only", "descriptor_version": "1" }
  ],
  "capabilities": {
    "workflow_create": true,
    "workflow_claim": false,
    "workflow_worker": true,
    "ui_actions": true,
    "settings_excluded": true,
    "order_submit": false,
    "order_cancel": false,
    "fund_transfer": false
  },
  "generated_at": "2026-07-25T12:00:00Z"
}
```

Bootstrap 只返回授权 Agent 操作所需的上下文快照，不调用模型，也不包含
`quick_commands` 或 `quick_commands_error`。画像投影与能力探测并行装配；客户端
取得有效 `context_version` 后即可把上下文标记为 ready，不得等待快捷指令生成。
客户端可按用户在 `localStorage` 保存最近一次 `{section, symbol}`，仅作为下一次
bootstrap 的请求提示，以避免先请求默认对象再切换造成的重复请求。不得在本地保存或
恢复 `context_version`、capabilities、画像投影或动作目录；这些授权事实仍须由本次
bootstrap 返回。

`POST /api/desk/quick-commands` 是快捷指令的唯一来源。请求包含
`stage=initial|after_answer|after_workflow`、`section`、`symbol` 和
`context_version`；`after_answer` 只接受 `decision_id`，`after_workflow` 只接受
`run_id`。服务端按 owner 读取直接回答或已完成 Run 的正式 Evidence，浏览器不得
提交回答正文、画像或证据。输出需通过标的关联、长度、近义去重和禁止动作校验；
首次不合格可修复一次，仍不合格时显式失败且不使用静态兜底。模型成功时返回恰好
三条非空、互不重复的安全指令；模型未配置、调用失败或输出不合同时返回空数组及
可见的 `quick_commands_error`。快捷指令加载或失败不改变已同步上下文的 ready 状态。

`profile_projection` 只能是 `SuitabilityProfileProjection`，不得包含收入、原始问卷、`objective_profile`、`dimension_scores`、账户凭据或私密证据。Agent `/agent/research` 注入的 `investor_profile` 必须同源投影。`ui_action_catalog` 不得包含设置、订单提交、撤单、资金划转、登录或任意 DOM/CSS 选择器。

`POST /api/desk/ui-actions` 接受 `{ action_id, context_version, parameters }`，回执仅 `applied | rejected | stale_context`。不在目录内或伪造禁止动作一律 `rejected`；`context_version` 前缀不匹配当前 owner 时返回 `stale_context`。
`add_to_watchlist` 仅在用户明确要求时由 Agent 提议，参数只含规范 A 股 `symbol`。
浏览器收到 `applied` 回执后复用正式自选写接口加入当前分组；没有分组时显式失败。
该动作不能创建/删除分组、移除标的或触发订单。

## 4. 行情与提醒合同

`GET /api/market/overview?symbols=000001.SZ,600519.SH` 返回每个标的的 `last`、`change_percent`、`provider_time`、`retrieved_at`、`frequency`、`freshness`、`session_alignment` 和质量诊断。`session_alignment` 区分当前交易时段与最近已发布交易日；它不替代供应商发布时间驱动的 `freshness`。涨跌幅必须由服务端使用权威昨收计算，昨收缺失时返回显式质量错误，不得静默输出不完整快照。失败时返回显式错误；最后成功行情可标为 `stale`，但不改写为新鲜。

`GET /api/market/bars?symbol=000001.SZ&frequency=daily|1m` 的范围由 PandaData 实际返回能力决定，浏览器不得通过 `limit` 截断。日线首次读取从服务端支持的历史起点请求，分钟线合并 PandaData 当前可用分钟数据；两者都按标的与频率写入服务端持久缓存并按时间去重。缓存新鲜时直接返回，过期后重新读取上游并合并；上游失败仍返回显式错误，不得把陈旧缓存冒充成功。生产缓存路径由 `FINANCE_GOD_MARKET_BAR_CACHE_PATH` 指向持久卷。

行情 `GET` 只读取并返回市场事实，不得同步创建数据质量工作流或写入业务状态。需要诊断或修复时必须由显式命令创建工作流，避免页面轮询把只读流量放大成持久写入。

当用户明确要求交易策略填写交易单时，`POST /api/workflows/desk` 仍先创建
`trade_plan_generation` 正式工作流，并在持久化 scope 中记录
`requested_ui_action=fill_trade_draft`。工作流完成后，浏览器只能从
`completed_node_artifacts` 引用的版本化 `trade_plan` 填写唯一启用且当前表单可表示的动作；
不得从报告自然语言抽取订单字段，不得猜测缺失数量，不得自动提交。

`GET /api/market/information-facts?symbol=000001.SZ&start_quarter=2026q1&end_quarter=2026q2` 返回 PandaData `get_fina_reports` 的公司财报披露事实。两个季度参数均为必填，格式为 `YYYYq1` 至 `YYYYq4`（小写 `q`，与 PandaData SDK 一致）。响应包含 `fact_kind=company_disclosure`、标的、请求时间以及每条事实的原始字段、上游端点、数据时间、摄取时间、证据引用和 freshness。它不生成新闻摘要、研报观点或交易结论。

`GET /api/market/news?limit=8` 返回服务端公开资讯 crawler 的规范化结果。响应包含 provider、实际抓取时间 `fetched_at`、`fresh|stale` freshness、`data_mode=real`、`trade_eligible=false`、warnings 与资讯条目；每条含稳定 id、标题、摘要、媒体来源、原文 URL、发布时间、板块和标签。综合资讯不伪装成当前股票的专属新闻。全源失败且没有可用真实缓存时返回显式 502；过期真实缓存只能以 `stale` 和 warning 返回，不能刷新 `fetched_at` 冒充新鲜。浏览器不直连第三方，原文 URL 只允许 `http`/`https`。

`GET /api/market/sentiment-facts?symbol=000001.SZ&start_date=20260701&end_date=20260723` 返回 PandaData `get_margin` 的融资余额原始观察值，仅支持中国股票。日期必须成对提供并使用 `YYYYMMDD`，省略时读取最近 30 个自然日。响应包含 `fact_kind=margin_balance` 与同样的来源证据字段；不返回恐惧/贪婪标签、情绪分数或交易信号。

两个事实接口都是只读、`trade_eligible=false` 的市场研究数据。默认情况下，上游为空、
权限不足、格式漂移或网络失败时返回显式错误；服务端不得把 mock 写进事实缓存、Evidence
或审计记录，也不得把模型推断伪装为上游事实。面向资讯流、情绪上下文、教学示例或
非操作性榜单的页面模块，可以在显式启用 `mock_fallback` 后使用独立 mock 数据集保底，
但必须满足：

- 只在真实请求已经失败或明确不可用后触发，空结果若是合法业务结果不得触发；
- 响应或前端状态携带 `data_mode=mock`、`fallback_reason`、`generated_at` 和
  `trade_eligible=false`；真实失败仍可见，并提供重试；
- mock 按模块整体替换，不与真实记录、陈旧缓存或其他标的数据混排；真实请求恢复后立即
  回到 `data_mode=real`；
- mock 只维持信息结构与交互演示，不得进入行情价格、估值、提醒触发、研究候选评分、
  Evidence、Agent 上下文/判断、风险校验、订单、成交、账户/持仓或合规审计；
- 行情/K 线、账户、持仓、订单、成交、执行、风控、画像、工作流状态和正式研究结论
  永远禁止使用 mock 代替失败。

建议只读接口统一返回 `data_mode=real|mock`；当 `data_mode=mock` 时，`source` 必须写为
Finance-God mock 数据集而非 PandaData 或第三方来源。浏览器依据该字段统一渲染披露，
不得自行猜测或在接口失败后本地生成随机内容。

`GET /api/alerts?cursor=...` 为历史分页；`GET /api/events?cursor=...` 为 SSE。告警事件的去重键由服务端决定，至少包含 `alert_id`、`severity`、`source`、`occurred_at`、`status` 和事实版本。

## 5. 模拟交易合同

- 每个当前仿真账户有且仅有一个服务端模拟时钟。建账/重置必须提交 `simulation_start_at`；服务端使用 PandaData 分钟数据验证历史交易日，并返回 `current_time`、固定 `speed=1`、状态、会话边界和修订号。
- 模拟业务事实使用模拟时间；幂等、租约和基础设施审计继续使用服务器真实时间。闭市暂停只能通过带期望修订的 `POST /api/simulation/clock/resume-next-session` 进入下一交易时段。
- 历史行情使用 `/api/simulation/market/*`，只返回当前模拟时间前已完成的 PandaData 1 分钟 bar，并绑定时钟修订；不得混用 `/api/market/*` 实时快照。
- 正式交易页使用 `POST /api/simulation/market-orders` 创建模拟市价单。浏览器只提交账户、标的、方向和数量；服务端以最近已完成分钟 bar 绑定引用证据，不信任客户端价格。
- 端点只接受 `buy|sell`，通过幂等命令完成风险校验、用户确认和订单提交；成功先返回 `accepted`。模拟时间进入下一分钟后，reconcile 使用下一根 PandaData bar 的开盘价成交并更新账本。缺 bar、闭市或上游失败时保持等待，不伪造成交。
- 账户、持仓、订单和成交始终标注模拟；行情仍为真实市场数据，两类状态不得混合。

## 6. 工作流合同

当前已上线接口：

| 接口 | 用途 | 成功响应 |
|---|---|---|
| `POST /api/workflows` | 创建持久 `WorkflowRun` | 首次创建返回 `201`；相同用户、相同 `Idempotency-Key` 与相同语义请求重放时返回 `200`；响应体均为裸 `WorkflowRun` JSON |
| `POST /api/workflows/desk` | 从交易台上下文创建持久 `WorkflowRun`，工作流类型由服务端选择 | 请求包含 `request_intent`、`section`、`symbol`、`context_version`；订单草稿复核还必须包含 `order_draft_id`、`order_draft_version`；首次创建 `201`，幂等重放 `200` |
| `GET /api/workflows/{run_id}` | 读取本人创建的运行状态 | `200` 与裸 `WorkflowRun` JSON；不存在或不属于当前用户时均为 `404` |
| `GET /api/workflows/{run_id}/progress` | 读取或长轮询真实进度快照 | `200`，返回状态、版本、已记录节点产物、已记录节点产物数量、注册节点总数、错误和终态标记 |

四个接口均要求 Bearer Token；`POST` 还必须携带 `Idempotency-Key`。通用创建请求至少包含 `workflow_key` 与 `request_intent`，并且必须提供以下其中一种版本化输入：

- `input_versions`：显式的 `{ object_type, object_id, version }` 数组；或
- `symbol` 与 `context_version`：交易台兼容写法，服务端将其规范化为一条 `instrument_context` 输入版本。

创建请求可选 `scope` 与 `task_plan_reference`。客户端不能提交工作流权限；权限由服务端命令边界决定。`WorkflowRun` 至少包含 `run_id`、`status`、`revision`、`workflow_key`、`workflow_version`、输入版本、已完成节点产物和错误。当前可能返回的状态以服务端领域模型为准，包括 `queued`、`running`、`completed`、`attention_required`、`failed`、`timed_out`、`blocked`、`cancel_requested`、`cancelling`、`cancelled` 与 `expired`。

同一 owner 同时最多存在一个 `queued | running | cancel_requested | cancelling`
的 Run。该不变量由数据库部分唯一索引和创建事务共同保证，而不是依赖浏览器状态。
新幂等键不能绕过它；冲突返回 `409 WORKFLOW_ALREADY_ACTIVE`，错误体携带
`active_run_id`，客户端必须恢复并继续跟踪该 Run。终态 Run 不阻止后续创建。

`progress` 不是节点事件流，也不返回浏览器推算的百分比。`completed_node_artifact_count` 只统计已持久化的节点产物；`total_node_count` 来自对应版本的服务端工作流注册表。节点产物尚未写入时，客户端只能呈现“后端已接受，等待 Worker 领取”，不能用计时器模拟步骤完成。

**Worker 已上线（P4）**：

- API 进程 lifespan 可按配置 `workflow_worker_enabled` 共启进程内 `WorkflowWorker`（`finance_god/application/workflow_worker.py`）。
- 独立守护：`backend/scripts/run_workflow_worker.py`（`--once` / `--interval` / `--batch-size`）。
- Worker 按 FIFO 读取 `queued` Run，以 `queued → running` 的 CAS 提交作为领取边界；每次状态、节点产物和执行审计使用短事务独立提交，禁止在模型调用期间持有数据库事务。
- Agent 节点调用真实统一 Multi-Agent runtime。只有真实 `AgentRun` 已生成且 Evidence bundle 保存成功，最终节点才可产生正式产物并进入 `completed`。
- 未接入生产适配器的确定性服务显式进入失败终态，不生成占位引用或伪造完成。
- `research_candidates`（注册表 v2）依次执行画像输入质量门、`candidate.score`
  和 Evidence 固化；该工作流只读、无交易资格，不调用模型生成股票名单。
- `portfolio_stress` 的确定性阶段读取模拟持仓投影并固化集中度计算；无账户或
  持仓事实时显式失败。
- `trade_plan_generation` 的确定性阶段调用同一 `TradePlanService` 生成版本化
  模拟计划，不自动生成或提交订单。
- `order_review` 必须绑定一条 `order_draft` 输入版本，调用模拟执行服务产生正式
  `RiskCheckResult`；输入版本变化时失败，最终订单提交仍需用户独立确认。
- 普通用户没有领取能力，`POST /api/workflows/claim` 不公开，bootstrap 固定返回 `workflow_claim=false`；`workflow_worker` 只表示服务端 Worker 任务正在运行。

任务档案、取消与派生重试已上线：

- `GET /api/workflows?cursor=&limit=20&status=` 按本人、请求时间倒序返回持久 Run；
- `POST /api/workflows/{run_id}/cancel` 对 queued 直接取消，对 running 提交协作式取消请求；
- `POST /api/workflows/{run_id}/retry` 以 `full|resume_failed` 创建不可变派生 Run，原始意图、scope 与版本化输入只从服务端读取；
- 派生关系使用 `parent_run_id`、`retry_mode`、`resumed_from_node_id` 审计；浏览器不得重传或改写原输入。

当前**未上线**：

- `GET /api/workflows/{run_id}/events?cursor=...` 节点事件流；
- 多 Worker `SKIP LOCKED` 租约与 Outbox/SSE 发布器；当前多 Worker 竞争由 `queued → running` CAS 保证只有一个执行者继续。

客户端始终以服务端 `WorkflowRun` 事实为唯一状态来源；创建成功表示已入队，Worker 推进后状态才会离开 `queued`。

`progress` 可选 `after_revision` 与 `wait_seconds`（最大 25 秒）。当当前修订未超过
`after_revision` 时，服务端等待真实修订变化或超时后返回当前快照；客户端同一 Run
只能保持一个长轮询请求，页面隐藏或切换 Run 时必须取消。进程内 Worker 在首次创建
queued Run 后接收即时唤醒信号；周期数据库轮询继续作为独立 Worker 与漏信号恢复边界，
幂等重放不得重复唤醒。

## 7. Agent 与动作合同

Agent 研究路径（`/agent/research`）只注入 `SuitabilityProfileProjection` 字段，不注入原始问卷或客观画像明细。正式任务真相是 `WorkflowRun`：交易台 Agent 面板通过 `POST /workflows/desk` 创建，由服务端选择工作流，再轮询 Run 与 progress。进入 `completed` 后按 `final_artifact` 读取本人可见的 Evidence bundle；前端只渲染结论、事实、推断、未知项和来源，不自行补全。

交易台前端使用统一 `AgentThreadMessage` 时间线。用户文字为普通气泡；AI 消息类型至少包括 `text`、`workflow`、`research_report`、`order_draft`、`order_receipt` 与 `error`。`research_report` 只能由终态 Evidence bundle 生成；`order_draft` 与 `order_receipt` 只能由模拟交易接口的真实响应生成。浏览器会话可暂存最近消息，但工作流和订单事实仍以服务端为准。

`/agent/desk/decision` 在 `mode=answer` 时直接返回 `answer_text`，客户端只展示该回复，不得再次调用 `/agent/research`。`mode=workflow` 时，`routing_reason` 保留为服务端决策记录；客户端只显示任务已创建及随后 Run 的真实状态，不展示内部路由说明。两种模式均可返回 `ui_actions`；每项只含目录内 `action_id`、字符串参数和由服务端绑定的请求 `context_version`。服务端必须在返回前复用 `/desk/ui-actions` 的参数策略校验，客户端仍须取得正式动作回执后才能改变界面。

普通与流式交易台回答必须由服务端装配同源的
`SuitabilityProfileProjection` 与当前模拟持仓最小投影。画像可用时不得声称风险等级、
损失容忍或方向缺失；模拟持仓可用时不得声称个人持仓缺失，空列表表示当前确实空仓。
持仓投影只包含标的、数量、可用数量、成本、均价与已实现盈亏，且必须标注模拟；
账户标识、设置、凭据和原始画像不得进入模型。画像或持仓读取失败必须以
`available/degraded` 显式表达，不得由浏览器回传或以演示数据静默替代。

直接回答的流式变体为 `POST /api/agent/desk/decision/stream`。服务端先完成执行方式与语义动作策略校验；`mode=workflow` 继续返回普通 JSON，`mode=answer` 返回 `application/x-ndjson`，事件顺序为 `start → delta* → done`，失败以 `error` 终止。`delta` 必须来自上游模型原生文本事件，浏览器不得用计时器拆分完整答案。完整答案只在 `done` 前固化；浏览器仅在流成功结束后应用已校验 UI 动作并请求后续快捷指令。连接中断或缺少 `done` 必须显示错误，不得把部分文本冒充完整回答。

服务端先以确定性规则固定 `answer | workflow` 和具体工作流，再由一次结构化 Agent
调用生成 `routing_reason`、`answer_text` 与 `ui_actions`。模型不能改变已批准模式或
工作流；动作仍须经过目录、参数和 `context_version` 三重校验。结构化输出不合格时
显式失败，不允许拆成额外模型调用或使用模板答案掩盖失败。

当意图包含“推荐股票”“选股”“可研究候选”等明确表达时，服务端固定选择
`research_candidates`，浏览器不分类。工作流完成后，客户端同时读取
`ResearchCandidateSet` Evidence 并刷新 `/workspace/candidates`；二者来自同一
画像化评分服务。候选只能进入研究或由用户另行申请交易计划，不能直接下单。

语义 UI 动作：

```json
{ "action_id": "select_symbol", "parameters": { "symbol": "600519.SH" }, "context_version": "desk:user-1:trading:600519.SH:1721900000" }
```

客户端只在动作 ID 位于 bootstrap 白名单、参数合法、`context_version` 仍匹配时应用；否则显示 `rejected` 或 `stale_context` 回执。订单提交与撤销始终由用户在独立确认流中执行，绝不经 Agent。

## 8. 提醒合同补充

- `GET /api/workspace/notifications`：仅未读列表。
- `GET /api/workspace/notifications/history?limit=50&include_read=true`：历史（含已读）。
- `POST /api/workspace/notifications/{id}/read`：标记已读并写 receipt。
- **Toast 关闭 ≠ 已读 ≠ 已处理**；历史接口只暴露持久化的 `unread|read`，不发明第三状态。

## 9. 决策日志与交易复盘合同

- 同一模拟账户和标的从零仓首次买入到再次归零构成一个 `TradeEpisode`；加仓和部分卖出复用活动案例。
- 每笔成交自动产生不可变 `TradeDecisionSnapshot`，冻结成交、行情版本、画像版本及当时可引用上下文；缺失主观字段保存为 `unavailable`，不得由浏览器或模型补造。
- 归零后生成终局 `TradeReview`，并创建来源为 `trade_review` 的画像审计新版本；客观画像字段从父版本复制，历史引用不重绑。
- `GET /api/trade-episodes` 及详情、decisions、review 接口使用统一 `{success,data,error,meta}` 包络；retry 要求 `Idempotency-Key`。
# 仿真保护策略合同

- `POST /api/simulation/protective-strategies` 接收 `account_id`、`instrument_id`、`quantity` 以及至少一个 `take_profit_price` / `stop_loss_price`，并要求 `Idempotency-Key`。
- `GET /api/simulation/protective-strategies` 返回当前用户的持久化策略及 `active`、`triggered`、`cancelled`、`failed` 状态。
- `POST /api/simulation/protective-strategies/{strategy_id}/cancel` 仅取消未触发策略。
- 浏览器只负责创建、查看和取消。价格绑定、行情监控、阈值判断、自动市价卖出、幂等和账本更新均由服务端负责。
- 服务端仅以 PandaData 归一化快照触发；观察失败必须记录并保持可重试，不得由前端定时器或本地价格替代。

# Agent 自学习摘要合同

- `GET /api/agent-learning/summary` 是鉴权只读接口，读取独立学习 Worker 原子写入的知识快照与最新周期记录。
- 返回 `status`（`healthy | stale | unavailable | error`）、`last_cycle`、`snapshot`、`recent_verified_lessons` 与 `freshness`；最近成果最多五条且只包含 `verified` 结论。
- `freshness` 以服务端配置的学习周期和最近完成时间计算。进程存在、API 可用或文件目录存在均不能单独证明 Worker 健康。
- 无首次快照、周期超时、连续失败或文件损坏必须返回可区分状态与原因；不得以演示数据、候选结论或旧内存状态伪造成功。
- 浏览器仅在进入复盘或用户刷新时读取，不负责启动 Worker、轮询学习进度、写知识或修改验证状态。
