# 前端统一设计规范

> 本规范以 `frontend/src/styles.css` 与 `frontend/src/views/TradingDeskView.vue` 等正式实现为准。
> 若历史原型、参考图或旧文案与本文冲突，以当前实现与本文为准。

## 1. 产品形态与信息边界

Finance-God 是桌面交易工作台，不是仪表盘或营销站。浏览器只承担展示、输入、会话和经服务端授权的语义操作；行情、账户、仓位、订单、工作流、告警和权限的唯一事实源都在服务端。

交易台采用**统一顶部栏 + 左右纸面分栏**：

- 左侧：事实与用户操作（总览 / 持仓 / 自选 / 交易 / 复盘）
- 右侧：Agent 的上下文、工作流回执与对话输入

两侧共用同一暖米色纸面与深墨文字。职责靠**双线分栏、细规则、字重与朱红强调**区分，不用黑白分栏、品牌蓝或卡片马赛克。

## 2. 视觉令牌

实现源：`frontend/src/styles.css` 中 `:root`。

| 语义 | 令牌 / 值 | 用途 |
|---|---|---|
| 纸面 | `--paper: #e9dec7` | 页面背景、交易台主栏 |
| 浅纸面 | `--paper-light: #f4ead4` | 输入区、弹层、选中浅底 |
| 墨色 | `--ink: #211a12` | 正文、主按钮、双线 |
| 次要墨色 | `--muted-ink: #625541` | 元数据、时间、说明、次要控件 |
| 规则线 | `--rule: rgb(45 34 22 / 62%)` | 分区横线、表格线 |
| 淡规则线 | `--faint-rule: rgb(45 34 22 / 15%)` | 行内分隔、虚线辅助 |
| 上涨 / 通过 | `--positive: #294f3e` | 仅收益、买入方向、通过态 |
| 下跌 / 风险 | `--risk: #8f3027` | 仅下跌、卖出、错误、风险文案 |
| 朱红强调 | `#c91418` | 当前工作区标签下划线、未读提醒圆点 |
| 主字体 | `--font-serif`（宋体系） | 正文、标题、导航 |
| 数字字体 | `--font-numeric`（Georgia 系） | 价格、金额、字标 `FINANCE GOD` / `AI AGENT` |

**禁止**：品牌蓝、渐变主界面、大圆角卡片矩阵、装饰性大阴影、广告式口号。
**允许的层次手段**：双线（`3–4px double`）、单线/虚线规则、字重、下划线动作、表格、标签栏、报刊式分栏。

### 2.1 排版与控件基线

- 全局 `font-variant-numeric: tabular-nums lining-nums`
- 圆角默认 `0`（直角编辑部气质）
- 可点击控件最小高度约 `44px`（桌面主操作）；次要文字按钮可略矮但需可点
- 主按钮 `.ink-button` / `.primary-button`：墨底浅纸字
- 次要动作：透明底 + 底边线或描边，悬停转朱红 / 墨色
- 焦点：`:focus-visible` 使用风险色描边；颜色不是唯一状态信号
- 减弱动效：尊重 `prefers-reduced-motion`

## 3. 交易台壳层布局

实现源：`TradingDeskView.vue` + `.desk-page` 样式块。

### 3.1 顶部栏 `.desk-topbar`

| 项 | 实际规格 |
|---|---|
| 高度 | 宽屏 **70px**；窄屏可收至约 58px |
| 底边 | `4px double var(--ink)` |
| 左侧 | `.desk-wordmark`：`FINANCE GOD`（数字字体大写）+ 副标「金融教父 · 投研与决策档案」 |
| 右侧 | 仅 **提醒**、竖向细分割线、**我的**（`.topbar-text-button` 文字 + 线框图标） |
| 未读 | 提醒按钮右上朱红小圆点（不依赖数字可读） |

顶栏**不放**行情状态长文案、设置入口、Agent 开关。交易台不提供布局设置入口，避免布局偏好遮挡主工作区。

### 3.2 主分栏 `.desk-spread`

宽屏（≥1024px）：

```
[ 左栏事实区 ] [ 双线分隔 ] [ Agent 栏 ]
```

- 左右栏固定等宽；Agent 保持展开并持续承载当前对话
- 分隔视觉：左栏右缘 `3px double` 墨线（非彩色分栏）
- 不提供宽度、收起、标签排序或重置布局设置

窄屏（&lt;1024px）：

- 保留同一路由 `/desk`
- 改为**上左栏、下 Agent**，左栏底边双线
- **不**另建移动导航或独立交易流

### 3.3 左侧工作区导航

- 横向标签，非侧栏图标导航：总览 / 持仓 / 自选 / 交易 / 复盘
- 字距偏大、报刊式；当前项字色朱红，底边 **3px `#c91418`**
- 标签顺序固定，不显示布局设置入口

### 3.4 工作区内容版式

各工作区共用：

- 页头 `.overview-heading`：大标题 + 右上「刷新」文字按钮
- 分区 `.overview-section`：顶部分隔线，标题 + 右侧元数据 `small`
- 表格 `.market-table`：细规则、右对齐数值、选中/悬停浅纸高亮
- 定义列表式摘要 `.market-sheet`：多列键值，用于账户摘要等
- 空态 / 错态：`.empty-data`、`.data-error`（风险色），禁止静默伪造成功

## 4. 五个左侧工作区内容

| 标签 | 主要对象 | 版式要点 |
|---|---|---|
| 总览 | 真实行情、情绪事实、资讯事实 | 行情用语义表格（标的 / 最新价 / 涨跌 / 涨跌幅 / 数据状态）；情绪与资讯为事实列表，**不**生成分数或摘要；符合降级合同的非交易关键模块可显示明确标识的 mock |
| 持仓 | 模拟账户、模拟仓位 | 账户三列现金摘要；仓位表；无实时行情时市值/浮盈写「行情不可用」 |
| 自选 | 分组、标的、可研究候选 | 分组管理与候选列表分区；候选不得直接下单 |
| 交易 | 模拟市价成交 | 标的、方向、数量一次提交；引用价必须来自服务端重读的真实行情；展示成交回执与最近成交 |
| 复盘 | 持仓周期决策档案、系统级 Agent 自学习摘要 | 案例表、不可变决策快照、成交事实、终局复盘与画像反馈；另以规则线分区展示学习 Worker 状态、最近周期与已验证成果；缺失信息明确显示“当时未记录” |

硬约束：

- 行情一律展示 PandaData **上游时间、频率、freshness**；失败显示陈旧/错误，**禁止**占位假价
- 账户 / 仓位 / 订单 / 成交标注 **模拟**，直至服务端返回真实业务类型
- 市场情绪只展示有来源的融资余额观察值；市场资讯只展示有来源的公司披露事实
- 资讯流、情绪上下文、教学示例和非操作性榜单等只读参考模块，可在服务端声明
  `trade_eligible=false` 且真实请求失败时使用 mock 保持页面结构可用。模块必须同时显示
  「模拟数据」、失败原因、生成时间与重试入口；mock 行不得伪装上游来源，不得与真实行混排，
  不得进入价格、估值、提醒、研究证据、Agent 判断、风控、下单、成交或审计

## 5. 右侧 Agent

实现源：`DeskAgentPanel.vue`。

| 区域 | 实际表现 |
|---|---|
| 标题 | `AI AGENT`（数字字体大号） |
| 标题栏附加信息 | 无；不展示内部 context 标识，也不放布局控制 |
| 任务运行信息 | 不设置独立运行区；正式任务气泡可展开/折叠，展开后集中展示该 Run 的状态、进度、节点和可折叠审计信息 |
| 线程区 | 按时间展示用户普通气泡和 AI 多功能气泡；正式任务、文字回复、研究报告、模拟订单草稿与回执、错误均保留在线程时间顺序中；宽屏线程在 Agent 栏内独立滚动，不随消息数量拉长整页 |
| 快捷指令 | 输入框上方 **恰好三条**；无卡片底；纵向一行一项；左侧描边对话气泡图标 |
| 输入 | 线框输入行 + 右侧发送图标按钮 |
| 收起态 | 竖排 rail，可一点展开；不改成模态抽屉或悬浮气泡 |

约束：

- 快捷指令由服务端模型根据当前工作区、标的和脱敏画像即时生成；不得使用工作区固定映射或前端模板兜底。成功时返回恰好三条不同角度的指令；生成不可用时显示明确状态并保留自由输入
- 设置、账户凭据、登录、订单提交、撤单、资金划转 **不**进入 Agent 上下文或动作目录
- 工作流只显示服务端 `queued/running/completed/failed/...`；无事件接口时只可写「后端已接受，等待执行器」，禁止浏览器计时模拟步骤
- Agent 自学习区只展示服务端知识快照中的已验证成果；候选结论、内部推理和完整审计不进入浏览器。Worker 未运行、周期陈旧或快照损坏必须明确显示，不得根据页面计时伪造健康状态
- `answer | workflow` 分流在服务端后台完成，不向用户展示路由说明；简单消息由对话 Agent 直接回复，前端不得把问候转成研究请求或按 workflow key 补静态文案
- 同一用户只运行一个写入型正式 Run；`queued/running/cancelling` 不阻断普通对话和只读问答。新输入仍由服务端判断 `answer | workflow`：直接回答可并发返回，需要正式 Run 的输入进入会话级待办队列，并在当前 Run 终态后顺序启动
- 活动 Run、意图与待办队列保存在会话存储中并在刷新后恢复；待办任务以可折叠列表呈现，可在启动前移出
- `completed` 只读取服务端 `final_artifact` 指向的 Evidence bundle；事实、推断、未知项和来源必须分区，失败不得替换为本地答案
- 研究报告与订单草稿必须作为 AI 消息气泡出现在时间线中；订单草稿明确标注模拟且只能引导至独立复核/确认流
- 普通回答直接采用 `/agent/desk/decision` 返回的 `answer_text`，不得为同一消息再发起一次研究请求

## 6. 提醒与「我的」

### 6.1 提醒

- 顶栏打开 `.reminder-panel` 浮层：浅纸面、墨线框、轻微偏移阴影
- 未读首条可出现右下 `.alert-toast`；约 8s 仅隐藏 Toast，**不**等于已读
- 关闭 / 已读 / 处理分别对应不同服务端状态

### 6.2 「我的」面板

- 顶栏打开 `.my-panel`（宽约至 760px 的编辑部浮层）
- 内部分页：**用户画像 / 钱包 / 交易记录 / 设置**
- 画像只读；设置仅本人读写
- 钱包与交易记录读模拟账户/订单/成交投影，失败与空态独立呈现
- 整个「我的」从 Agent capability、上下文、工具与审计载荷中排除

## 7. 用户画像与研究候选

画像展示风险等级、损失容忍、投资期限、经验、流动性、完整度、低置信维度、版本与教育限制。原始问卷、收入和敏感证据不直接给 Agent 或渲染到交易台主栏。

「推荐购入股票」在产品中统一称为 **可研究候选**。候选须附带画像投影版本、行情上游时间、适配理由、风险/反方证据、未知项和下一步研究动作；不得直接触发买卖或自动下单。

## 8. 非交易台页面（同源令牌）

登录、引导访谈、画像报告、管理设置与交易台共享同一套纸面/墨色令牌，但结构不同：

| 页面类型 | 结构要点 |
|---|---|
| 登录 / 注册 | 左深墨品牌栏 + 右表单；直角、细线、主按钮墨底 |
| 引导访谈 | 进度条、双列选择题、对话区浅纸气泡 |
| 画像报告 | 深墨 hero、指标带、手册式候选卡（报告页允许有限卡片，交易台主栏不用卡片矩阵） |
| 管理设置 | 左侧能力标签 + 右侧表单工作区 |

不得在交易台主栏照搬报告页的大卡片矩阵。

### 8.1 实时语音通话

- 访谈页与交易台 Agent 可在原工作区内切换到 Live 通话状态，不使用模态抽屉或悬浮气泡。
- 通话必须由用户主动发起，持续显示连接、收音、思考、播报或错误状态，并提供静音和挂断。
- 实时字幕分别标明用户与 AI；挂断后最终字幕进入原消息时间线。
- 原始音频不落盘。服务失败时明确返回文字模式，不以浏览器语音能力静默替代。
- 交易台语音模式仍遵守 Agent 工具、上下文和交易权限边界。

## 9. 可访问性与故障原则

- 语义：`nav`、`table`、`form`、`dialog`/`aside` 浮层、`details`、可聚焦 `separator`
- 所有交互有可见焦点；涨跌同时使用颜色与符号/文案
- 请求失败必须显示人类可读原因（及错误码若有）、最后成功数据时间（若有）和刷新入口
- 降级必须可见、可追溯且按模块整体切换；真实数据恢复后自动退出 mock，不保留混合列表
- 除已声明的非交易只读参考模块外，不得静默降级、伪造成功或伪造市场事实
