# 前端统一设计规范

## 1. 产品形态与信息边界

Finance-God 是桌面交易工作台，不是仪表盘或营销站。浏览器只承担展示、输入、会话和经服务端授权的语义操作；行情、账户、仓位、订单、工作流、告警和权限的唯一事实源都在服务端。

交易台采用统一顶部栏与左右同宽的双页工作区：左侧是事实和用户操作，右侧是 Agent 的推理、工作流和对话。两侧必须使用相同的暖米色纸面底色与深墨色文字；职责由双细线和空间层级区分，不用黑白分栏或蓝色强调。

## 2. 视觉令牌

| 语义 | 令牌 | 用途 |
|---|---|---|
| 纸面 | `--paper: #e9dec7` | 两个主栏和背景 |
| 浅纸面 | `--paper-light: #f4ead4` | 输入、选中单元和弹层 |
| 墨色 | `--ink: #211a12` | 正文、主要动作、双细线 |
| 次要墨色 | `--muted-ink: #625541` | 上游时间、范围、状态说明 |
| 上涨/通过 | `--positive: #294f3e` | 仅用于收益、买入、通过 |
| 下跌/风险 | `--risk: #8f3027` | 仅用于下跌、卖出、错误、风险 |

不使用品牌蓝、渐变、圆角卡片矩阵、装饰性阴影或广告式口号。优先使用规则线、表格、标签栏、栏目标题和可读的数字排版。

## 3. 布局与响应式

- 主画布：1440px；顶部栏高度 70px，左侧显示 `FINANCE GOD` 及“金融教父 · 投研与决策档案”，右侧只保留提醒与“我的”入口。
- 桌面宽度 ≥1024px：左右主栏为 `1fr / 1fr`，中间 3px 双细线；左栏内部为首行横向标签与工作区。
- 宽度 <1024px：保留 `/desk`，改为左栏在上、Agent 在下；不创建移动专用导航或独立交易流。
- Agent 宽屏默认展开；用户可折叠为可见 rail，偏好持久化。设置不随 Agent 折叠或露出为 Agent 能力。
- 工作区的筛选、标签排序、面板可见性和尺寸应由浏览器持久化；重置需可见、可逆。

## 4. 左侧工作区

左侧横向标签只包含：总览、持仓、自选、交易。钱包、交易记录、用户画像和设置集中到顶部“我的”面板；提醒从顶部独立入口打开。不得隐藏持仓、自选、交易或提醒入口。

总览页依次展示：可选择的真实行情概览、数据时间/频率/freshness、市场情绪事实和市场资讯事实。市场情绪只能展示有来源的融资余额观察值；市场资讯只能展示有来源的公司披露事实，禁止生成新闻摘要、情绪分数、走势线或占位内容。持仓、钱包、订单、成交一律标注“仿真”直到服务端返回真实业务类型；行情一律显示 PandaData 上游时间，失败时显示陈旧或错误状态，禁止替换为占位价格。

## 5. 右侧 Agent

Agent 使用一个共享右侧面板，随当前工作区、标的和上下文版本变化。输入框上方始终恰好显示三条推荐快捷指令：无边框、无卡片底、纵向一行一个、左对齐，使用描边对话气泡图标形成 icon rail。

三条指令由服务端的 `DeskBootstrap` 或 `AgentSuggestion` 合同生成；在合同到位前可使用确定性本地映射，但必须显式基于当前左侧状态，不能声称是个性化 AI 推荐。设置、账户凭据、登录信息、订单提交、撤单和资金划转不进入 Agent 上下文或动作目录。

工作流运行时显示服务端真实 `queued/running/completed/failed/...` 状态和节点事件。完成后默认折叠，用户可展开；无事件接口时只可显示“后端已接受，等待执行器”，不能用浏览器计时模拟步骤。

## 6. 用户画像与研究候选

画像展示风险等级、损失容忍、投资期限、经验、流动性、完整度、低置信维度、版本与教育限制。原始问卷、收入和敏感证据不直接给 Agent 或渲染到交易台。

“推荐购入股票”在产品中统一称为“可研究候选”。候选必须附带画像投影版本、行情上游时间、适配理由、风险/反方证据、未知项和下一步研究动作；不得直接触发买入、卖出或自动下单。

## 7. 提醒与设置

重大行情、数据质量和系统异常通过可关闭 Toast 提示，并在提醒记录中留存。自动消失仅改变 Toast 可见性；关闭、已读、确认处理分别由不同服务端状态表达。

用户画像、钱包、交易记录和用户设置位于顶部“我的”面板；用户画像只读，设置只由用户本人读写。整个“我的”面板必须从 Agent 的 capability discovery、上下文、工具调用与审计载荷中排除。

## 8. 可访问性与故障原则

使用语义导航、表格、表单、`dialog` 和可聚焦按钮；所有交互有可见焦点，颜色不是唯一状态信号，支持 `prefers-reduced-motion`。请求失败必须显示错误码/人类可读原因、最后成功数据时间（若有）和刷新入口；不得静默降级、伪造成功或伪造市场事实。
