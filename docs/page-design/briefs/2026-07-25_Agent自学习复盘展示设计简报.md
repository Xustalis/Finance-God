# Agent 自学习复盘展示设计简报

## 用户与操作场景

模拟交易用户在复盘持仓周期时，需要确认系统级 Agent 自学习是否真实运行，并查看最近通过验证的研究结论；该信息不等同于当前单笔交易的复盘结论。

## 页面任务与主要对象

`/desk` 的“复盘”工作区增加“Agent 自学习”只读分区，主要对象为持续学习 Worker 的知识快照、最近周期状态和已验证学习成果。

## 信息层级与工作区区域

沿用交易台顶栏、双栏和 Agent 侧栏。左栏复盘案例列表之后增加规则线分区：先显示运行状态与最近周期，再显示知识版本、累计成果数和最近已验证结论；不使用卡片矩阵或完整内部审计。

## 真实数据来源、频率、新鲜度与失败状态

数据来自后端对 `snapshot.json` 与最新 `cycles/cycle-*.json` 的只读投影。页面进入复盘或用户刷新时按需读取，不轮询。无快照、周期陈旧、文件损坏和接口失败均显示明确状态，不伪造运行中或学习成果。

## 主要操作与启用条件

用户可随复盘页刷新全部内容，也可在自学习接口失败时独立重试。该区域只读，不允许浏览器启动 Worker、修改知识或把候选结论提升为已验证结论。

## 受影响路由与桌面宽度

仅 `/desk`；1440px 沿用既有双栏，低于 1024px 保持同路由上下排列，低于 680px 状态摘要与结论元数据改为单列。

## 视觉论点

以暖纸面、深墨文字和细规则线表达可审计状态；系统状态用明确文字而非新增强调色，学习结论采用紧凑纵向列表，与单笔交易时间线保持清晰边界。

## 内容计划

运行状态与最近周期用于确认 Worker 是否工作；知识摘要用于说明已积累规模；最近验证成果用于展示实际学习内容；错误与空态用于解释为什么当前没有可展示结论。

## 交互论点

刷新期间仅替换按钮状态，不卸载已有结果；独立错误可原位重试；状态变化不使用装饰性动效，并尊重既有 `prefers-reduced-motion`。
