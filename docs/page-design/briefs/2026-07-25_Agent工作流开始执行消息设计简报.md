# Agent 工作流开始执行消息设计简报

## 用户与操作场景

交易台用户在右侧 Agent 对话中提交正式研究任务，需要在不展开技术信息的情况下确认服务端 Worker 是否已经开始执行。

## 页面任务与主要对象

页面任务是展示工作流受理、开始执行和终态；主要对象是 Agent 时间线中的正式任务消息。

## 信息层级与工作区区域

仅调整 `/desk` 右侧 Agent 正式任务消息：摘要标题随状态变化，活动工作流默认展开，在对话中直接显示真实状态、节点和进度。顶部栏、左侧工作区、提醒和「我的」不改动。

## 真实数据来源、频率、新鲜度与失败状态

标题严格映射服务端 `WorkflowRun.status`。`queued` 表示已受理但尚未领取，`running` 表示已开始执行，终态按服务端状态显示；不使用浏览器计时或模拟阶段。

## 主要操作与启用条件

用户无需额外操作。工作流轮询取得真实状态后，同一条任务消息更新标题；`queued | running | cancel_requested | cancelling` 默认展开并显示节点、进度和审计入口，终态仍可按需展开回看。

## 受影响路由与桌面宽度

仅 `/desk`；适用于所有宽度，未改变现有宽屏双栏及窄屏上下布局。

## 视觉与交互论点

沿用现有纸面、墨色、直角任务消息与折叠交互，不引入新颜色、卡片或动效。开始执行信息放在时间线消息摘要中，与朱红导航当前态及双线分栏不冲突。
