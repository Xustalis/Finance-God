# 正式交易台重建设计简报

## 用户与操作场景

面向已完成画像的个人投资者，在桌面端查看真实 PandaData 行情、管理仿真账户，并通过右侧 Agent 发起研究和工作流。页面为操作工作区，不是营销页。

## 页面任务与主要对象

主对象为“当前交易上下文”：当前左侧工作区、所选标的、用户画像投影、行情新鲜度和未读提醒。左侧展示并编辑用户可操作的工作对象；右侧 Agent 读取经授权的上下文并返回语义动作或工作流结果。

## 信息层级与工作区

- 顶栏：产品名、行情连接状态、提醒和“我的”图标入口；“我的”从 Agent 能力目录中排除。
- 左右同色、同宽的纸张工作区，以细规则线分开。左侧窄导航仅含信息、持仓、自选、交易；钱包、交易记录、画像和设置集中在“我的”面板，右侧为常驻 Agent。
- 右侧输入框上方仅保留三条纵向快捷指令，随左侧上下文更新；每项以描边对话图标起始，无卡片、无描边、无阴影。
- 工作流运行时展示后端 `WorkflowRun` 状态和 run ID；无节点事件时只显示后端已接受/当前状态，不能用前端计时伪造步骤。

## 真实数据、频率与失败状态

- 行情：`GET /api/market/overview`，默认 60 秒轮询；显示 PandaData 上游时间、频率和 freshness。失败时显示错误/陈旧状态，不显示编造价格。
- 用户画像：`GET /api/v1/profiles/me/latest`，仅显示风险、期限、经验、完整度、版本等可读摘要；首次研究由后端根据画像投影和行情产生，前端不在浏览器自行推荐买入。
- 提醒：`GET /api/workspace/notifications`。未读提醒以可关闭 Toast 展示，并在八秒后只自动收起 Toast；记录由服务端留存。
- Agent：`POST /api/workflows` 创建后端工作流，`GET /api/workflows/:run_id` 查询状态。三条快捷指令由当前左侧状态的确定性映射生成，待服务端推荐合同到位后替换。

## 主要操作与启用条件

用户可切换左侧工作区、选择标的、刷新行情、发起研究和准备仿真交易方案。订单提交和撤单不属于 Agent 可执行范围；分析请求要求后端工作流可用，设置仅由用户本人提交。

## 路由与桌面宽度

主路由为 `/desk`；旧交易链接均重定向至该工作区。以 1440 px 为主画布；低于 1024 px 保持同一路由、改为上下布局和可见 Agent 折叠轨道，不建立单独移动交易流。

## 视觉与交互论点

视觉：暖米色纸张、深墨文字、双细线和密集表格构成编辑部金融终端，左右两边使用同一底色而非黑白对照。
内容：左侧负责事实与输入，右侧负责决策过程与协作；画像是推荐的限制条件，不是装饰性人格标签。
交互：标的/工作区改变立即改变右侧上下文和三条快捷指令；请求开始后显示可观测状态，返回后自动收起。
