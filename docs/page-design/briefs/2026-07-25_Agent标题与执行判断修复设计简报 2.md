# Agent 标题与执行判断修复设计简报

## 用户与操作场景

用户在 `/desk` 观察 Agent 的任务分流和真实工作流进度，希望标题区去掉内部上下文与局部布局按钮，并要求执行判断来自真实 Agent；当前量化监测失败也必须修到真实数据请求可完成。

## 页面任务与主要对象

主要对象是当前 Agent turn、服务端执行决策和 WorkflowRun。标题栏只保留 `AI AGENT`；任务线程用用户/Agent 聊天气泡承载对话，后台执行决策不显示，复杂任务继续展示真实节点状态。

## 信息层级与工作区区域

- 顶栏、左侧标签与业务内容不变。
- 右侧 Agent：标题 → 用户气泡 → Agent 气泡或节点任务 → 证据/错误 → 三条快捷指令与输入。
- 静态能力说明、“本次任务范围”、内部 context 标识、Agent 栏“重置布局”和“收起”删除；工作区布局菜单、分栏拖拽与收起 rail 一并删除，Agent 保持展开。

## 真实数据来源、频率、新鲜度与失败状态

- 简单消息由已配置的 Ark 对话模型实时回答；模型不可用或返回空内容时显示显式错误，不调用研究 Agent 伪装回复。
- 工作流状态和节点产物来自服务端持久化进度。
- 市场状态监测继续读取 PandaData；历史波动率使用完整研究窗口，空集或 schema 错误仍保持失败，不伪造值。

## 主要操作与启用条件

发送只在服务端 context、Agent 能力或 Workflow Worker 能力满足时启用。服务端完成 `answer | workflow` 判断后继续执行；判断说明不展示，简单消息直接显示真实对话模型回复。页面不提供布局设置。

## 受影响路由与桌面宽度

仅 `/desk`；验证 1440px、1024px 与当前 787px 浏览器宽度，同一路由保持挂载。

## 视觉与交互论点

沿用暖纸面、深墨、细线和朱红状态色，不引入新颜色或卡片体系。删去标题栏的技术噪声与重复布局控制，让运行状态成为首要信息；不增加动画。
