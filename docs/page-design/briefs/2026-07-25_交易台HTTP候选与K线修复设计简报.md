# 交易台 HTTP、候选与 K 线修复设计简报

## 用户与操作场景

用户通过生产 HTTP 地址使用交易台：建立模拟账户、维护自选、查看画像候选，并在总览或交易区切换日线、周线、月线。

## 页面任务与主要对象

消除非安全上下文缺少 `crypto.randomUUID` 导致的写操作失败；将现金/固收画像没有股票候选呈现为正常适用范围；确保非分钟周期读取 PandaData 日线而不是把单日分钟数据聚合成巨型蜡烛。

## 信息层级与工作区区域

- 壳层、顶栏和右侧 Agent 不改动。
- 持仓、自选及 Agent 写操作只替换内部请求 ID 生成方式。
- 自选候选区沿用原空态位置，显示方向中文名与功能边界。
- 总览和交易区沿用原 K 线组件与周期标签。

## 真实数据来源、频率、新鲜度与失败状态

- 分时、5 分、15 分、1 小时读取 PandaData 1 分钟 bars 后在浏览器聚合。
- 日线、周线、月线读取 PandaData 日线；周/月只在日线基础上聚合。
- 生产能力目录未启用指数分钟线；指数仅开放日线、周线和月线。切换到指数时自动回到日线。
- 历史模拟的报价池排除三只仅用于实时总览的基准指数，避免无关能力告警污染持仓读取状态。
- 默认启动保持实时模式，历史演示必须由模拟账户用户显式进入。
- 指数上下文进入交易区时切换为默认可交易股票，保证订单草稿只引用可验证的个股真实行情。
- 历史模拟 K 线显式传递 `1m` 或 `daily`；周线和月线由模拟时点前的真实日线聚合，不再把单日分钟行情冒充长周期。
- 日线服务端窗口限制在上游与适配器允许的范围内；失败继续显式显示，不回退假 K 线。
- 股票候选只覆盖服务端已有股票方向；现金/固收等方向不生成股票候选，属于正常状态。

## 主要操作与启用条件

建立账户、自选写入和 Agent 待办在 `randomUUID` 不可用但 `getRandomValues` 可用时仍生成 RFC 4122 UUID。周期按钮保持可点击；切换周期后仅使用对应真实频率。

## 受影响路由与桌面宽度

仅 `/desk`；1440px 与 `<1024px` 同路由布局均不改变。

## 视觉与交互论点

沿用现有纸面、墨色、朱红当前态与规则线，不新增颜色或卡片。现金/固收无股票候选使用 `.empty-data`，只有真实候选读取失败继续使用风险色。
