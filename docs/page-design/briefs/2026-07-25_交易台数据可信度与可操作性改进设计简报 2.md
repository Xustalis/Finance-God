# 交易台数据可信度与可操作性改进设计简报

## 用户与操作场景

面向在桌面浏览器中同时查看真实行情、公司/融资事实并进行仿真交易的零售与专业用户。用户会频繁切换标的、刷新数据、核对引用价、处理提醒，并在服务异常时判断当前页面是否仍可操作。

## 页面任务与主要对象

本次改进 `/desk` 的数据可信度与关键操作门禁，主要对象为 PandaData 行情与事实批次、仿真账户状态、订单草稿引用价、提醒状态和自选分组。目标是避免跨标的旧事实、读取失败误建账户和“关闭即已读”，并补齐键盘与窄屏操作。

## 信息层级与工作区区域

- 顶栏：不改变入口，仅修正提醒 Toast 的隐藏语义。
- 总览：行情表显示最后成功读取时间；事实区同时呈现同标的旧数据与当前错误，不显示其他标的数据。
- 持仓：区分账户未知、不存在、可用和读取失败；只有明确不存在时开放建账。
- 自选：同步当前分组编辑字段，宽表在窄屏内滚动。
- 交易：在草稿创建前显示当前标的真实引用价、上游时间、频率与 freshness，并在草稿摘要中保留引用价与有效期。
- Agent：本次不改变能力、上下文或工作流协议。

## 真实数据来源、频率、新鲜度与失败状态

- 行情来自 `/api/market/overview`，沿用共享轮询；显示 PandaData 上游时间、实际频率、freshness 与客户端最后成功读取时间。
- 公司披露与融资余额事实来自现有两个只读事实接口。新请求只渲染响应 `symbol` 与当前标的一致的数据；同标的刷新失败可保留最后成功批次，但必须同时显示错误。
- 仿真账户、持仓、订单和成交仍明确标注仿真。账户读取失败不得等同于账户不存在。
- 不引入占位价、示例事实或浏览器推算的成功状态。

## 主要操作与启用条件

- 建立仿真账户：仅账户状态为 `absent` 时启用。
- 创建订单草稿：必须有与输入标的一致、价格有效且市场状态可用的真实引用行情。
- 标记提醒已读：仅用户点击“标记已读”时调用服务端；隐藏 Toast 不改变提醒状态。
- 选择行情标的：提供可聚焦按钮，支持键盘 Enter/Space。

## 受影响路由与桌面宽度

- 路由：仅 `/desk`。
- ≥1024px：保持可调双栏与 Agent rail。
- <1024px：保持同路由上下布局。
- ≤680px：行情、持仓、自选候选和交易计划表格在所属区域内横向滚动，不撑破页面。

## 视觉与交互论点

视觉论点：继续使用暖米色纸面、深墨文字、细规则与朱红当前态，数据错误只使用既有风险色，不增加卡片、蓝色或新强调色。

内容计划：先呈现工作区标题和数据状态，再呈现可操作表格/表单，最后呈现错误与最后成功时间；每个区域只承担一种数据或操作责任。

交互论点：选标的按钮使用行内下划线与选中底色强化可操作性；刷新保留旧数据时用错误文案和时间戳明确状态变化；窄屏仅通过布局重排和局部滚动适配。沿用现有快速颜色/边线过渡，并继续尊重 `prefers-reduced-motion`。
