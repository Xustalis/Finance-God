# 正式任务运行信息入口设计简报

## 用户与操作场景

用户在 `/desk` 提交正式研究任务后，需要从消息线程中的创建回执直接查看该 Run 的真实运行状态，而不是自行回到右栏顶部寻找运行区。

## 页面任务与主要对象

主要对象是服务端 `WorkflowRun`、对应 progress 节点及审计元数据。创建回执本身是可展开任务气泡；当前与历史 Run 都在原气泡内显示运行信息。

## 信息层级与工作区区域

顶栏、左侧工作区和浮层不变。右侧 Agent 不再设置独立固定运行区；正式任务在消息线程中以可折叠任务气泡承载状态、进度、节点与审计信息。宽屏 Agent 栏受当前视口高度约束，消息线程独立滚动，不随历史消息无限拉长页面。

## 真实数据来源、频率、新鲜度与失败状态

当前 Run 读取 store 中由 `/api/workflows/{run_id}` 与 progress 长轮询同步的服务端事实，点击时主动刷新一次。历史 Run 展开时按 `run_id` 通过任务历史与详情接口读取，但不切换到任务档案页面。加载、失败和无节点状态沿用现有明确文案。

## 主要操作与启用条件

点击正式任务气泡的摘要即可展开或折叠。展开当前 Run 时主动刷新服务端状态；展开历史 Run 时直接在同一气泡中加载节点、错误与审计信息。

## 受影响路由与桌面宽度

仅 `/desk`。覆盖 1440px 主画布、1024px 双栏边界与小于 1024px 的同路由上下布局。

## 视觉与交互论点

视觉沿用暖纸、深墨、细规则与现有任务气泡，不新增颜色或浮层。加减号与原生 `details` 同时表达展开状态，节点信息仅在用户需要时出现；输入区保持在 Agent 栏底部。
