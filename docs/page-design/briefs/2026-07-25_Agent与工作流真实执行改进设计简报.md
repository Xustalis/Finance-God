# Agent 与工作流真实执行改进设计简报

## 用户与操作场景

用户在 `/desk` 当前工作区和标的上下文中提出问题，需要先知道 Agent 为什么直接回答或为什么启动工作流，再确认任务是否真正被服务端接受、由哪些角色处理、何时完成、产物是什么以及失败原因。参考图只用于“判断说明—分工列表—逐项状态”的信息层级；视觉继续遵守 Finance-God 暖色编辑式终端规范。

## 页面任务与主要对象

右侧 Agent 从“所有输入都创建工作流并显示状态表格”改为一个有服务端判断能力的执行线程。主要对象为 `ExecutionDecision`、用户意图、单 Agent 回答或 `WorkflowRun`、逐节点 execution audit、最终 evidence bundle、错误与来源；左侧交易操作和“我的/设置”边界不变。

## 信息层级与工作区区域

- 顶栏、左侧四工作区、提醒和“我的”不改。
- Agent 标题下先显示当前工作区、标的和服务端 `context_version`。
- 线程区按顺序显示：服务端执行方式说明 → 当前用户意图 → 真实角色/服务任务卡 → 完成产物或失败原因。
- 任务卡只承载同一任务的执行单元，不形成仪表盘卡片矩阵；默认显示角色、职责和真实状态。
- Run key、revision 与节点计数移入默认折叠的“执行记录与技术信息”。
- 完成产物使用结论、事实、推断、未知项和来源的纵向规则线列表。
- 输入区继续保留恰好三条快捷指令；已有活动任务时禁用新提交，避免覆盖。

## 真实数据来源、频率、新鲜度与失败状态

- 判断：`POST /api/agent/desk/decision`，服务端返回 `answer | workflow`、原因、工作流名称与是否可启动。
- 简单回答：`POST /api/agent/research`，限制为一个受治理 Agent；AgentRun 证据保存失败时返回显式 502，不向页面返回答案。
- 创建：`POST /api/workflows/desk`，服务端根据工作区和意图选择正式工作流并返回持久 `WorkflowRun`。
- 状态：`GET /api/workflows/{run_id}`；进度：`GET /api/workflows/{run_id}/progress`，活动任务每 2 秒轮询，页面隐藏时暂停，恢复立即刷新。
- 产物：Run 完成后按 `final_artifact` 读取 `/api/evidence/{object_type}/{object_id}?version=...&tier=advanced`。
- 任务节点：progress 的 `nodes[]` 由服务端 execution audit 推导，前端不猜测执行中或完成。
- runtime 不可用、节点失败、证据保存失败、产物缺失或权限失败均显示服务端错误；不提供本地答案、假节点或默认结论。

## 主要操作与启用条件

- 提交指令：必须有非空意图、服务端 `context_version`，且 `agent_answer=true` 或 `workflow_create=true + workflow_worker=true`，当前没有 queued/running/cancelling 任务。
- 简单问题：服务端决定为 `answer` 后调用一个 Agent；不创建 WorkflowRun。
- 多步骤问题：服务端决定为 `workflow` 且 `can_start=true` 后才创建 WorkflowRun。
- 查询状态：有活动 Run 时启用。
- 快捷指令：与自由输入走同一创建入口和幂等边界。
- 新任务：上一任务进入终态后可创建；终态产物仍留在当前线程直到新任务明确开始。
- Agent 仍不具备设置、订单提交、撤单或资金划转能力。

## 受影响路由与桌面宽度

影响生产 `/desk`，不新增路由。重点验证 1440 px、1024 px、900 px；小于 1024 px 时沿用上下排列，同一线程、进度和产物完整保留。

## 视觉与交互论点

**视觉论点**：把右栏处理成一份可追溯的编辑部任务稿——暖纸面、深墨字、细规则、紧凑分工列表和证据清单。任务卡使用同一纸面内的细线分组，不使用蓝色选中态；朱红仍只用于当前运行态/未读，错误使用风险色。

**内容计划**：当前上下文负责定位；任务回执负责运行状态；证据产物负责回答；输入区负责下一次明确动作。没有 Hero、营销文案或实现说明。

**交互论点**：

1. 提交后先显示服务端执行方式与原因；简单问题直接显示单 Agent 回答，多步骤问题显示真实任务卡；
2. 任务状态只随 execution audit 更新，不用动画模拟进度；
3. 技术记录默认折叠，用户无需阅读 workflow key/revision 才能理解任务；
4. 终态产物在同一线程展开，刷新页面后从持久 Run ID 恢复；`prefers-reduced-motion` 下不依赖过渡表达状态。
