# 画像用户生成真实研究候选旅程设计简报

## 用户与操作场景

已完成投资画像并选择权益方向的用户进入交易台，通过右侧 Agent 发起“结合画像生成可研究候选”。用户需要看到正式任务的真实状态、可追溯 Evidence，以及自选工作区中由服务端重新计算的真实候选。

## 页面任务与主要对象

页面任务是把画像投影、PandaData 行情、持久工作流和候选列表串成一条可恢复的研究旅程。主要对象为 `WorkflowRun`、`ResearchCandidateSet` Evidence 和服务端候选投影。

## 信息层级与工作区区域

- 顶栏与交易台壳层不变。
- 左侧自选工作区展示分组、候选来源、画像版本、上游时间、解释维度、反方证据和未知项。
- 右侧 Agent 在线程内展示 queued、running、终态和正式 Evidence。
- 不新增浮层、卡片或独立移动流程。

## 真实数据来源、频率、新鲜度与失败状态

- 画像来自服务端适当性投影及其版本。
- 候选行情只接受 PandaData 且必须带上游时间；缺少真实行情的标的不进入候选。
- 工作流状态与节点产物来自持久服务端记录，客户端不模拟进度。
- 画像不适用、历史模式、行情不可用和读取失败分别展示；不得被“尚无自选分组”状态覆盖。

## 主要操作与启用条件

- 用户完成画像、选择权益方向且 Desk Bootstrap 宣告工作流和 Worker 可用后，才可创建候选研究任务。
- 工作流完成后读取正式 Evidence，并刷新 `/workspace/candidates`。
- 候选只用于继续研究；忽略和恢复操作使用幂等键；任何候选都不会自动下单。

## 受影响路由与桌面宽度

- 受影响路由：`/desk`。
- 1440px 保持左右等宽纸面工作区。
- 1024px 以下保持同一路由上下排列，不新增移动导航。

## 视觉与交互论点

沿用暖米色纸面、深墨文字、双线分栏和朱红当前态，不引入新强调色。候选状态使用现有规则线、表格和无卡片状态区；工作流继续使用可展开的线程纸片。交互只强化状态归属和稳定测试标识，不增加装饰动画。
