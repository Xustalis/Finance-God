# 四个交易台工作区设计简报

## 用户与操作场景

已登录用户在 1440px 桌面交易台中阅读真实行情、管理仿真持仓与自选、完成一次需本人确认的仿真下单；右侧 Agent 始终跟随当前工作区和标的。参考图只确定 `FINANCE GOD` 顶栏、暖米色双栏、双细线和报刊式密度，不提供页面数据或结论。

## 页面任务与主要对象

单一路由 `/desk` 包含四个共享壳层工作区：总览（真实行情与事实）、持仓（仿真账户与持仓）、自选（分组及可研究候选）、交易（订单草稿至回执）。主要对象分别为行情快照、仿真账户/仓位、自选分组/候选、仿真草稿/订单。

## 信息层级与工作区区域

- 顶部：左侧 `FINANCE GOD` 与“金融教父 · 投研与决策档案”，右侧只有提醒和我的。
- 左侧：总览、持仓、自选、交易横向标签；各页采用细规则表格和表单，不使用卡片矩阵。
- 右侧：`AI AGENT`、当前工作区/标的/context version、真实工作流回执、三条快捷指令、输入框。
- 我的：画像、钱包、交易记录、设置独立于 Agent 上下文和动作能力。

## 真实数据来源、频率、新鲜度与失败状态

行情只来自 `/api/market/overview`，通过单一 Pinia 缓存合并基准标的、持仓和自选标的，60 秒轮询；页面隐藏暂停，恢复立即刷新。页面显示 PandaData 上游时间、频率和 freshness；请求失败或没有行情时明确写“行情不可用”，不造价。公司披露事实请求携带上一季度到当前季度的 `start_quarter/end_quarter`。账户、持仓、订单均由 `/api/simulation/*` 读取并标注仿真；自选和候选来自 `/api/workspace/*`；工作流只显示 `/api/workflows` 的服务端状态/错误。

## 主要操作与启用条件

用户确认初始资金后才创建仿真账户。订单必须有 `current` 且已发布/交易中的真实行情引用价格，依次经过草稿、风险复核、软风险确认（如有）、摘要确认、最终提交；所有写命令携带 `Idempotency-Key`。候选仅是研究对象，可忽略，不能直接买卖。自选编辑依赖服务端修订版本，冲突时提示刷新。

## 受影响路由与桌面宽度

影响 `/desk`、`/login?redirect=/desk`。`/desk?preview=1` 不再绕过认证；用户须用已有账号登录。≥1024px 为等宽双栏，<1024px 同一路由改为上下布局。

## 视觉与交互论点

暖象牙纸、深墨文字、双线分栏、朱红当前标签与风险、深绿收益；标题使用衬线/数字字体建立财经档案的版式。快捷指令贴近输入框、纵向排列、无卡片底和阴影，使用描边对话图标形成左侧 icon rail。
