# 模拟账户时钟与 Agent 超时修复设计简报

## 用户与操作场景

用户进入 `/desk` 查看既有模拟账户、持仓及右侧 Agent。历史账户可能创建于模拟时钟功能上线前；模型生成快捷指令或回答可能超过通用客户端的 30 秒等待时间。

## 页面任务与主要对象

持仓区必须读取服务端唯一的模拟账户与模拟时钟；Agent 区必须等待服务端真实模型结果。主要对象为当前模拟账户、账户级模拟时钟和 Agent 请求。

## 信息层级与工作区区域

不改顶栏、左侧工作区、右侧 Agent 布局或浮层。仅恢复持仓事实读取，并调整 Agent 请求的端点级等待预算与错误文案。

## 真实数据来源、频率、新鲜度与失败状态

账户和时钟来自 PostgreSQL 持久状态；迁移为缺少时钟的历史账户补齐一对一时钟行，不修改余额、持仓或成交。Agent 继续读取服务端模型结果；70 秒客户端预算只用于模型端点，超时显示中文错误。

## 主要操作与启用条件

账户读取成功后显示余额和持仓；真实 5xx 仍暂停建账。Agent 上下文同步后可提交，模型端点等待 70 秒，普通行情和业务 API 仍为 30 秒。

## 受影响路由与桌面宽度

仅 `/desk`，所有现有桌面宽度。布局与断点不变。

## 视觉与交互论点

沿用纸面、墨色、风险色错误和双栏结构，不新增视觉令牌。修复后移除错误状态，恢复既有账户表格与 Agent 输入。
