# Agent 任务范围透明化最小完善设计简报

## 用户与操作场景

用户位于 `/desk`，准备向常驻 Agent 提交研究问题。用户需要在提交前确认当前工作区、标的、所用组合、行情新鲜度、画像投影以及执行产物边界，避免不知道 Agent 正在分析什么。

## 页面任务与主要对象

把现有 `DeskBootstrap`、选中行情、仿真组合和服务端 Agent 路由汇总为固定可见的“本次提交依据”。新增只读预览合同 `POST /api/agent/desk/preview`，复用正式提交的路由规则且不调用模型、不创建工作流、不写审计记录。主要对象仍是当前交易台上下文；不新增会话、推荐或自动交易对象。

## 信息层级与工作区区域

- 顶栏、左侧四个工作区和浮层不改动。
- 右侧 Agent 标题与执行结果不改动。
- 在 Agent 标题和消息线程之间固定显示工作区、标的、所用仿真组合、行情时间/新鲜度/频率、画像版本、执行方式、预计角色和产物类型。
- 未输入任务时，执行方式显示“输入任务后预览”；输入停止 300ms 后由服务端返回“直接回答”或正式工作流名称，以及预计角色和产物类型。前端不复制关键词路由。
- 输入区仍保留恰好三条快捷指令和一个主输入。

## 真实数据来源、频率、新鲜度与失败状态

- 行情范围直接读取当前 `DeskQuote`，显示 PandaData 供应商、`frequency`、`freshness` 和 `provider_time`。
- 画像只读取服务端脱敏 `profile_projection` 的版本与可用状态。
- 仿真组合读取服务端组合投影；未加载或未建立时显式显示对应状态。
- 执行方式、角色和产物读取服务端 `DeskAgentPreview`；预览与正式提交共享服务端路由函数，正式提交仍以 `DeskAgentDecision` 为准。
- Bootstrap 或行情失败沿用现有可见错误；范围摘要显示“行情不可用/上下文未确认”，不生成占位值。

## 主要操作与启用条件

主要操作仍是提交研究任务；仅当服务端上下文存在，且直答或工作流能力经服务端确认时启用。提交依据只读并固定可见，不改变权限和提交条件。

## 受影响路由与桌面宽度

- 路由：`/desk`
- 目标：1440px 主画布；1024px 以下沿用同路由上下堆叠；680px 以下保持范围摘要可换行。

## 视觉与交互论点

- 视觉论点：暖米色纸面、深墨文字和细规则构成“任务委托单”，不使用卡片、品牌蓝或新强调色。
- 内容计划：当前对象与组合 → 行情与画像版本 → 执行方式与预计产物 → 原有快捷指令/输入。
- 交互论点：上下文随工作区、标的、行情和服务端决策即时更新；现有 Agent 面板与布局过渡保持不变；不增加装饰性动效。
