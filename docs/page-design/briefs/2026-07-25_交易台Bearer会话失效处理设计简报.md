# 交易台 Bearer 会话失效处理设计简报

## 用户与操作场景

已登录用户打开 `/desk` 或保持页面运行时，Bearer token 可能过期、失效或对应用户已停用。用户需要被明确带回登录流程，不能停留在工作区看到后端英文认证异常。

## 页面任务与主要对象

页面任务不变；本次主要对象是浏览器用户会话，以及 `/api/v1`、交易域 `/api`、Agent 流式请求和提醒 SSE 的统一 401 失败状态。

## 信息层级与工作区区域

顶栏、左侧五个工作区、右侧 Agent 和浮层均不改动。401 是全页面会话边界：清除失效 token 与用户投影后进入 `/login`，不在任一区域保留不可操作的旧状态。

## 真实数据来源、频率、新鲜度与失败状态

认证结论只来自服务端 HTTP 401。客户端不猜测 token 有效期、不刷新或伪造会话；普通请求、Agent 流和提醒 SSE 收到 401 时执行同一失效处理，原请求仍以明确错误结束。

## 主要操作与启用条件

服务端返回 401 时自动清理 `finance-god-token` 与 `finance-god-user` 并跳转 `/login`。非 401 请求不改变会话；登录页收到迟到的 401 时只清理状态，不重复导航。

## 受影响路由与桌面宽度

影响 `/desk` 及共享普通用户认证的页面；所有桌面宽度行为一致。无布局、断点或移动流程变更。

## 视觉与交互论点

沿用现有纸面/墨色令牌，不引入颜色、表格、规则或浮层变化；不影响朱红当前态和双线分栏。认证失败直接退出已失效工作区，因此不新增可能与业务错误态冲突的视觉层。
