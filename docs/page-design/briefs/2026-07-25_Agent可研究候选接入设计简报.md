# Agent 可研究候选接入设计简报

## 用户与操作场景

已认证用户在 `/desk` 右侧 Agent 输入“推荐股票”“结合画像生成可研究候选”等意图，希望得到与本人画像、当前仿真持仓和真实行情一致的研究入口，而不是买入指令。

## 页面任务与主要对象

页面任务是创建并跟踪服务端 `research_candidates` 工作流。主要对象为画像投影版本、方向过滤后的候选集、五项解释维度、反方证据、未知项和 PandaData 上游时间。

## 信息层级与工作区区域

- 顶栏、工作区导航和双栏壳层不变。
- 右侧 Agent 继续显示 WorkflowRun 状态和通用 Evidence 分区，不增加本地生成答案。
- 左侧自选工作区继续使用现有候选表；候选工作流完成后刷新同一服务端候选合同。
- 不新增浮层、颜色、卡片或订单动作。

## 真实数据来源、频率、新鲜度与失败状态

- 画像：服务端 `SuitabilityProfileProjection`，显示并引用画像版本。
- 持仓：当前仿真账户投影，仅用于组合适配。
- 行情：PandaData 标准化快照，候选携带 provider、upstream time、freshness。
- 无画像、教育模式、无支持方向、行情不可用或服务未接入均产生可读未知项/失败状态；不以模型猜测或默认股票替代。

## 主要操作与启用条件

主要操作为提交研究意图。启用条件仍是服务端确认 `workflow_create`、`workflow_worker` 和 `context_version` 可用；候选结果只允许进入研究与后续“申请交易计划”，不能直接下单。

## 受影响路由与桌面宽度

仅 `/desk`。1440px 主画布、1024px 以下同路由上下布局和 680px 窄屏行为均不改变。

## 视觉与交互论点

沿用纸面/墨色、朱红当前态、双线分栏和现有语义表格。此次不引入新强调色或布局；候选 Evidence 使用现有事实、推断、未知项、来源区域，候选明细继续由自选区表格承载。
