# 模拟账户状态恢复设计简报

## 用户与操作场景

已登录用户进入 `/desk` 的持仓或交易工作区，页面需要先确认服务端模拟账户是否存在。

## 页面任务与主要对象

主要对象是服务端模拟账户事实。修复后，既有账户即使尚无历史模拟时钟记录，也必须显示为已存在；不得开放重复建户。

## 信息层级与工作区区域

顶栏、工作区标签、右侧 Agent 和浮层均不改动。仅修正左侧持仓/交易区消费的账户合同类型。

## 真实数据来源、频率、新鲜度与失败状态

账户来自 `GET /api/simulation/accounts/current`。`simulation_time` 可为空，表示既有账户尚无历史时钟；账户读取失败仍显示明确错误，不伪造账户状态。

## 主要操作与启用条件

仅服务端明确返回 `NOT_FOUND` 时启用建立模拟账户；服务错误继续暂停建户。已有账户不因时钟记录缺失而失效。

## 受影响路由与桌面宽度

受影响路由为 `/desk`，覆盖现有全部桌面宽度；无布局或断点变化。

## 视觉与交互论点

沿用现有纸面、墨色、朱红当前态与双线分栏；不新增视觉元素、强调色、表格或浮层。
