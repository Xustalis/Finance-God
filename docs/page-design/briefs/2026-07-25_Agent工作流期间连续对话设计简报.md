# Agent 工作流期间连续对话设计简报

## 用户与操作场景

交易用户在长时研究任务执行期间，仍需查询进度、解释术语、读取当前行情并追问已经完成的节点；这些只读对话不应被正式任务占用。

## 页面任务与主要对象

右侧 Agent 面板同时承载普通对话、一个活动正式工作流和后续正式任务待办。消息、活动 Run 与待办意图使用独立状态。

## 信息层级与工作区区域

顶栏与左侧工作区不改。右侧时间线保留对话和运行状态；输入区在 Run 执行时保持可用；输入区上方增加默认折叠的正式任务待办列表。

## 真实数据来源、频率、新鲜度与失败状态

回答与 `answer | workflow` 判断来自 Agent decision 接口；活动 Run 与进度继续来自工作流状态接口。待办仅保存用户意图，不伪造 Run；创建失败时保留在队列。

## 主要操作与启用条件

上下文同步且 Agent 回答或工作流能力可用时允许发送。直接回答可并发；一个正式 Run 活动时，新的正式任务加入队列，可在启动前移出，当前 Run 终态后按顺序启动。

## 受影响路由与桌面宽度

仅 `/desk`。1440px 维持双栏；1024px 以下沿用同路由堆叠。

## 视觉与交互论点

沿用暖纸、深墨、虚线规则和直角控件，不引入新强调色或卡片。输入占位文案明确“任务执行中仍可提问”。
