# 交易台真实可用性闭环设计简报

## 用户与操作场景

面向在 1440px 桌面端读取真实市场数据、建立仿真账户、人工确认订单并调用研究 Agent 的用户。验收以真实 HTTP 请求和真实浏览器点击为准，服务启动、静态构建或 mock 测试不能单独证明可用。

## 页面任务与主要对象

本次收口 `/desk` 的真实行情、仿真订单和 Agent 三条主链。主要对象是 PandaData 标准化行情及版本、仿真草稿/订单回执、提交后的真实 bar、持久 `WorkflowRun` 和 Evidence。

## 信息层级与工作区区域

- 顶栏和四个横向工作区标签不改版。
- 总览继续显示真实行情、上游时间、实际频率、披露事实和融资事实。
- 持仓与自选继续承载仿真账户及研究候选；错误状态按工作区隔离。
- 交易区从真实引用行情进入草稿、复核、确认、提交，并显示服务端订单号与真实撮合状态。
- 右侧 Agent 由 bootstrap 的实际 Worker 能力启用，显示持久 Run 的节点数、修订和终态证据。
- 「我的」和提醒浮层不改变 Agent 权限。

## 真实数据来源、频率、新鲜度与失败状态

- 行情、bar、公司披露和融资事实来自后端 PandaData 适配器；浏览器不接收凭据。
- 行情 `GET` 无业务写副作用；缓存到期触发后台刷新时保留原上游 freshness，不提前伪标 stale。
- 财报事实只查询已经完成的两个季度；上游空值或错误显式显示。
- 草稿由服务端重新读取行情并绑定价格与版本。浏览器值不一致时失败关闭。
- 撮合只接受订单提交后的真实 bar；盘后无后续数据时正常保留 `accepted` 等待成交，不把等待态报成失败。
- readiness 同时检查数据库结构和已配置的后台任务存活，不以进程已监听端口代替可用性。

## 主要操作与启用条件

- 创建草稿：已有仿真账户、标的有正的真实价格、行情市场状态为 `in_session` 或 `released`。
- 风险复核与摘要确认：严格按服务端 revision 和 summary hash 推进。
- 最终提交：必须由用户点击，成功响应直接返回订单回执。
- 尝试撮合：仅已接受或部分成交订单可操作；无后续真实 bar 时保持等待。
- Agent：bootstrap 实际确认 `workflow_create` 和 `workflow_worker` 后才启用；活动 Run 禁止覆盖。

## 受影响路由与桌面宽度

- 路由：`/desk`；同时移除 `/desk` 被误列入 legacy redirect 的重复路由。
- 1440px：双栏工作区和展开 Agent。
- 1024px 以下：保持 `/desk` 挂载并使用既有紧凑布局；不新增移动交易流。

## 视觉与交互论点

沿用暖米纸面、深墨、细规则、方角与朱红当前态，不引入新颜色或卡片矩阵。订单回执和撮合动作留在交易工作区的规则线区域；失败用现有风险文案，同时保留订单真实状态。错误拆分为订单错误与交易计划错误，避免跨工作区产生错误归因。
