# 交易台真实资讯抓取设计简报

## 用户与操作场景

交易用户在总览中查看近期公开财经资讯，用于理解市场背景。资讯是非交易只读参考，不能代替行情、公司披露、定价证据或订单引用价。

## 页面任务与主要对象

将总览中误作“资讯”的公司财报披露字段替换为服务端公开资讯爬虫结果。每条资讯展示标题、媒体来源、发布时间和原文链接；PandaData 公司披露合同继续独立保留，不混入新闻流。

## 信息层级与工作区区域

顶栏、工作区标签和右侧 Agent 不变。左侧总览在行情与融资余额事实之后展示“市场资讯”；使用现有细规则列表，不新增卡片、浮层或布局入口。

## 真实数据来源、频率、新鲜度与失败状态

- 数据由服务端 crawler 从已配置的公开财经资讯源抓取，浏览器不直连第三方。
- 服务端返回抓取时间、发布时间、来源、原文 URL、freshness 与 `trade_eligible=false`。
- 缓存有效期由服务端统一控制；前端随总览刷新读取，不独立轮询第三方。
- 全源失败且没有可用缓存时显示明确错误，不把空数组伪装成成功；过期真实缓存必须标记 stale。
- 不为资讯生成静默 mock，不让新闻进入定价、估值、Agent 正式证据、风控、订单、成交或审计。

## 主要操作与启用条件

用户可打开通过协议校验的 `http`/`https` 原文链接；链接在新窗口打开并隔离 opener。历史模拟模式继续隐藏现实资讯，避免未来信息污染。

## 受影响路由与桌面宽度

仅影响 `/desk` 总览。1440 px 保持现有双栏；低于 1024 px 保持同一路由与现有紧凑布局。

## 视觉与交互论点

沿用暖纸、深墨、细规则和朱红错误状态，不引入新强调色。发布时间与来源作为低层级元信息；标题承担主信息。真实 stale/error 使用文字和语义状态表达，不只依赖颜色。
