# 交易台 Agent 响应与工作流提速设计简报

## 用户与操作场景

已登录用户在 `/desk` 右侧 Agent 输入问候、概念问题、界面操作或研究任务。用户需要尽快看到首条真实回复，并持续看到服务端已持久化的工作流状态；不能用降低模型、减少 Agent 或伪造进度换取速度。

## 页面任务与主要对象

主要对象是一次 Agent turn 和至多一个活动 `WorkflowRun`。首条回复合并为一次结构化模型调用；研究任务创建后即时唤醒进程内 Worker，并按服务端 revision 长轮询真实进度。

## 信息层级与工作区区域

顶栏、左侧四个工作区、提醒和「我的」不变。右侧 Agent 时间线继续展示用户消息、直接回答、任务卡和最终 Evidence；等待文案细分为生成回复、创建任务、等待 Worker 和执行节点。

## 真实数据来源、频率、新鲜度与失败状态

决策来自 `/agent/desk/decision`；Run 与节点状态来自 `/workflows/{run_id}` 和 `/progress`；最终报告来自 `final_artifact` 指向的 Evidence。长轮询最长 20 秒，只有 revision 变化才更新；失败显示接口错误，不使用本地答案或模拟进度。

## 主要操作与启用条件

Bootstrap 必须确认 `agent_answer`；工作流还需 `workflow_create` 与 `workflow_worker`。活动 Run 期间禁用新提交。页面隐藏、切换 Run 或卸载会取消观察请求，恢复可见后立即读取。

## 受影响路由与桌面宽度

仅 `/desk`。1440px、1024px 与小于 1024px 的既有布局均不改变。

## 视觉与交互论点

沿用纸面、墨色、朱红当前态和双线分栏，不新增颜色、卡片或动效。变化只涉及 Agent 气泡内的功能性状态文字与后台观察方式。
