# 快捷指令全程建议系统设计简报

## 用户与操作场景

用户在 `/desk` 的常驻 Agent 中开始问题、收到直接回答或完成研究工作流。快捷指令应随当前标的和最新正式结果变化，帮助用户理解结论、核查反方风险并推进下一步，而不是重复展示首屏通用问题。

## 页面任务与主要对象

把输入框上方恰好三条快捷指令升级为阶段化建议。主要对象是服务端确认的当前交易台上下文、直接回答和工作流 Evidence；客户端不提交画像、回答正文或证据。

## 信息层级与工作区区域

- 顶栏、左侧四个工作区、提醒和「我的」不改动。
- 右侧 Agent 输入区增加“快捷指令 / 正在生成下一步建议”状态和“换一组”文字动作。
- 三条指令仍为无卡片纵向列表；点击继续走统一 Agent 提交流程。
- 直接回答或工作流完成后，在同一区域替换建议，不在消息时间线增加第二套建议组件。

## 真实数据来源、频率、新鲜度与失败状态

- `initial` 使用服务端 `context_version`、权威标的名称和脱敏画像。
- `after_answer` 只读取服务端短期保存、按 owner 隔离的直接回答。
- `after_workflow` 只读取本人已完成 Run 的 `final_artifact` Evidence。
- 生成失败返回空数组和明确错误；不使用静态模板或旧上下文建议。

## 主要操作与启用条件

点击指令需要当前服务端上下文有效且无活动 Run。“换一组”复用当前阶段与结果引用；活动工作流、生成中或上下文缺失时禁用。切换工作区或标的会使旧请求失效。

## 受影响路由与桌面宽度

- 路由：`/desk`
- 目标：1440px 主画布；1024px 以下沿用同路由上下排列；输入区在窄宽度保持文字动作和三条指令可换行。

## 视觉与交互论点

- 沿用暖米色、深墨、细虚线和现有焦点样式，不增加强调色、卡片、浮层或装饰动画。
- 内容计划：阶段状态与重生成动作 → 三条建议或明确错误 → 自由输入。
- 交互论点：建议更新是原位置替换；加载和禁用状态防止重复提交；迟到响应不得改变新上下文。
