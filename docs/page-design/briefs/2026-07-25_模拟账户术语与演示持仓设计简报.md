# 模拟账户术语与演示持仓设计简报

## 用户与操作场景

面向在 `/desk` 查看账户、持仓和交易记录的桌面用户。用户需要一致的“模拟”业务术语，并希望通过正式交易接口产生一笔可供界面演示的持仓。

## 页面任务与主要对象

将用户可见的“仿真账户、仿真持仓、仿真订单、仿真交易”等术语统一为“模拟账户、模拟持仓、模拟订单、模拟交易”。演示持仓必须来自服务端模拟交易接口及账本投影，不在前端写死或伪造。

## 信息层级与工作区区域

顶栏、横向工作区标签、双栏壳层与右侧 Agent 布局不变。左侧持仓区继续依次展示模拟账户现金摘要和模拟持仓表；交易区、Agent 订单气泡、“我的”钱包与交易记录同步使用“模拟”术语。

交易区 K 线图关闭第三方图表库自动注入的归因链接，保留 PandaData 来源、上游时间与行情状态。

## 真实数据来源、频率、新鲜度与失败状态

交易引用价仍由服务端读取 PandaData 标准化行情，模拟订单、成交和持仓由服务端交易接口及模拟账本产生。行情失败、持仓读取失败和交易失败继续显式展示，不以示例价或前端静态数据代替。

## 主要操作与启用条件

只有模拟账户存在、标的真实行情可用、数量合法且资金或可卖数量充足时，才可通过模拟交易接口提交订单。成功后重新读取账户、成交和持仓投影。

## 受影响路由与桌面宽度

影响 `/desk` 的持仓、交易、Agent 订单消息和“我的”浮层，以及画像报告中通向交易台的限制说明；覆盖现有 ≥1024px 双栏和 <1024px 同路由自适应布局。

## 视觉与交互论点

沿用暖米色纸面、深墨文字、朱红当前态和双线分栏，不新增颜色、卡片或动效。术语变更不改变信息密度；持仓演示复用既有语义表格和真实失败状态。图表归因通过 `lightweight-charts` 初始化选项关闭，不使用覆盖层或 CSS 隐藏。
