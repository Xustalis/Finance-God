# Agent 工作流集中观察区设计简报

## 用户与操作场景

用户在正式研究任务运行期间继续对话，同时需要稳定观察任务状态，不能依赖在消息时间线中寻找某个气泡。

## 页面任务与主要对象

右侧 Agent 面板新增唯一活动 Run 的集中观察区。主要对象是活动 Run、真实节点快照、完成产物计数和技术审计信息。

## 信息层级与工作区区域

顶栏与左侧工作区不改。Agent 内部顺序为：标题、提交依据、任务运行区、对话线程、待办队列、输入区。任务气泡只保留创建回执。

## 真实数据来源、频率、新鲜度与失败状态

状态、节点、修订和错误继续读取工作流 Run/Progress 接口及既有轮询；无节点时明确显示等待 Worker 或等待节点落库，不生成本地进度。

## 主要操作与启用条件

存在 `activeWorkflow` 时显示运行区。用户可刷新状态、展开审计信息，并在服务端允许的活动状态下取消任务。

## 受影响路由与桌面宽度

仅 `/desk`。1440px 双栏中任务区固定在 Agent 上部；窄于 1024px 仍使用同一路由堆叠，节点区内部限高滚动。

## 视觉与交互论点

沿用暖纸、深墨、双线和虚线，不新增卡片矩阵或强调色。运行中的节点以既有朱红订线提示，完成态使用既有正向色。任务区与消息区通过双线分隔。
