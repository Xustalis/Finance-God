# Agent 语义动作控制交易台设计简报

## 用户与操作场景

已认证用户在 `/desk` 与 Agent 对话；Agent 可用版本化语义动作协助定位和准备左侧工作，但不能操作 DOM、提交订单、撤单、划转资金或访问设置。

## 页面任务与主要对象

主要对象是当前工作区、标的、筛选/排序条件、指定记录、研究候选、未提交交易草稿、工作流产物、提醒和交易计划。所有动作统一返回 `applied`、`rejected` 或 `stale_context`。

## 信息层级与工作区区域

顶栏、四个左侧标签和右侧 Agent 壳层不变。动作由服务端目录授权并校验参数，前端 Pinia 单一执行器应用；交易草稿只预填，最终提交继续由用户独立确认。

## 真实数据来源、频率、新鲜度与失败状态

行情仍来自 PandaData 后端适配器和共享轮询控制器；动作不生成行情。刷新动作读取真实行情，失败沿用可见错误/陈旧状态。账户、仓位、草稿、订单和交易计划继续明确为仿真业务数据。

## 主要操作与启用条件

动作 ID 必须存在于 bootstrap 的 `ui_action_catalog`，参数必须通过服务端语义校验，动作携带的 `context_version` 必须与页面当前版本完全一致。缺目录、非法参数或选择器参数返回 `rejected`；页面上下文变化返回 `stale_context`。

## 受影响路由与桌面宽度

仅 `/desk`。1440px、1024px 以上双栏和 1024px 以下同路由上下布局均沿用现有实现。

## 视觉与交互论点

沿用暖米色、深墨、规则线和朱红当前态，不引入新强调色或卡片。动作产生的预填和定位复用现有工作区控件；不改变双线分栏、Agent rail 或响应式结构。
