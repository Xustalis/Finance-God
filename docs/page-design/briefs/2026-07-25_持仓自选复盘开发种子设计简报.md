# 持仓、自选与复盘开发种子设计简报

## 用户与操作场景

本地开发者使用测试用户进入 `/desk`，需要在不伪造正式行情和候选的前提下检查持仓、自选与复盘工作区。

## 页面任务与主要对象

通过显式开发命令创建模拟账户的账本、订单、成交、持仓、自选关系和交易复盘，使三个工作区读取正式 API 后具备轻量内容。前端不保留第二套 mock 数据。

## 信息层级与工作区区域

顶栏、横向工作区标签、左侧表格与右侧 Agent 均不改变。持仓继续显示模拟账户摘要与持仓表；自选继续显示分组、标的与真实候选状态；复盘继续显示案例表、决策时间线、复盘结果和真实 Agent 自学习状态。

## 真实数据来源、频率、新鲜度与失败状态

账户、订单、成交、持仓和复盘是开发测试用户的模拟业务数据，经正式服务写入并由现有 API 读取。市值与浮盈仍只读取 PandaData 行情；行情失败时显示不可用。研究候选仍由画像投影与真实行情生成，Agent 自学习仍读取真实 Worker 摘要。

## 主要操作与启用条件

开发者显式执行 `make seed-dev-workspace`。命令只允许 development 环境，要求测试用户已存在；账户不存在时建立模拟账户，已有数据只补稳定种子对象，资金不足时明确失败且不修改初始资金。

## 受影响路由与桌面宽度

仅影响 `/desk` 的持仓、自选与复盘数据内容。沿用 1440px 主画布、≥1024px 双栏和 <1024px 同路由上下布局。

## 视觉与交互论点

沿用暖米纸面、深墨排版、规则线、语义表格和朱红当前态，不新增颜色、卡片或动效。`frontend-skill` 的工作台原则用于保留高密度但克制的表格结构；此次不通过装饰填空，而以可操作的正式模拟业务对象提升信息密度。
