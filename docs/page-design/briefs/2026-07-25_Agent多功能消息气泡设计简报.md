# Agent 多功能消息气泡设计简报

## 用户与操作场景

普通投资者与专业交易者在 `/desk` 右侧常驻 Agent 中连续提问、发起研究，并查看仿真订单草稿与提交回执。用户不需要理解工作流内部结构，但可以按需展开技术记录。

## 页面任务与主要对象

主要对象从“单个当前工作流”调整为按时间排列的 `AgentThreadMessage`。用户消息为普通文字气泡；AI 消息按文字回复、任务进度、研究报告、仿真订单草稿、仿真订单回执和错误分别渲染。

## 信息层级与工作区区域

顶栏、左侧四个工作区和浮层不改。右侧 Agent 保留标题、消息时间线、三条快捷指令和输入区。研究报告与订单草稿均位于 AI 气泡内部；工作流技术记录仍可折叠。

## 真实数据来源、频率、新鲜度与失败状态

普通回答来自 `/agent/desk/decision` 的 `answer_text`，不重复请求研究接口。任务状态来自 `/workflows/{id}` 与 `/progress`；研究报告来自 `final_artifact` Evidence；订单草稿和回执来自仿真交易 HTTP 响应。失败生成显式错误消息，不伪造报告、价格或订单成功。

## 主要操作与启用条件

普通回复要求 `agent_answer`；工作流要求 `workflow_create` 与 Worker 可用。订单草稿仍由交易区使用真实引用行情创建，气泡只展示并引导用户前往复核；最终提交必须经过独立风控与用户确认。

## 受影响路由与桌面宽度

仅 `/desk`。沿用 ≥1024px 双栏、<1024px 上下排列和 ≤680px 紧凑布局。

## 视觉与交互论点

视觉论点：暖纸消息流配深墨用户气泡，AI 多功能气泡使用朱红左规则线和报刊式内部横线；不引入蓝色或圆角卡片矩阵。

内容计划：普通对话优先；执行任务显示真实状态；终态报告与订单对象提供摘要和下一步动作。

交互论点：新消息进入同一时间线；执行状态在原消息更新；研究和订单详情使用原生 `details` 展开，并尊重 reduced-motion。
