# Agent 任务运行信息读取修复设计简报

## 用户与操作场景

用户在 `/desk` 的 Agent 时间线中展开已创建的正式任务，需要读取该 Run 的真实状态与节点进度。

## 页面任务与主要对象

主要对象是任务消息已保存的服务端 `run_id`。展开任务时直接按该 ID 读取 Run 与 progress，不依赖当前已加载的任务历史分页。

## 信息层级与工作区区域

顶栏、左侧工作区、右侧 Agent 布局和浮层均不改变。只修正正式任务气泡内部运行信息的读取路径。

## 真实数据来源、频率、新鲜度与失败状态

状态来自 `GET /api/workflows/{run_id}` 与 `GET /api/workflows/{run_id}/progress`。不存在、无权或服务失败继续显示服务端错误，不使用本地状态替代。

## 主要操作与启用条件

用户展开非活动任务气泡时，使用气泡携带的 `run_id` 直接读取；活动任务仍使用现有刷新与长轮询。

## 受影响路由与桌面宽度

仅 `/desk`；1440px 与低于 1024px 的现有布局均不改变。

## 视觉与交互论点

沿用暖纸、深墨、规则线与风险色错误状态；不引入新颜色、容器、动效或布局变化。
