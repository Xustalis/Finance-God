# 重大行情站内实时推送设计简报

## 用户与运行场景

已认证的零售或专业交易用户在 `/desk` 关注当前标的、模拟持仓和自选标的。
开市期间需要在重大价格变化被服务端确认后，于 75 秒检测目标内看到可追溯提醒；
页面断线、隐藏或刷新不能造成提醒丢失或自动已读。

## 页面任务与主要对象

主要对象是持久化 `MarketAlert → Notification → UserEvent`。用户在顶栏查看未读数，
通过 Toast 获知新事件，在提醒历史中查看标的、PandaData 上游时间、检测时间和状态，
并显式标记已读。

## 信息层级与工作区

顶栏只保留提醒入口与未读数；普通提醒在右下 Toast 短暂出现，高优先级提醒持续保留；
完整记录位于原有提醒纸面浮层，不改变左右交易台与 Agent 分栏。

## 数据、频率与失败状态

- 行情源：PandaData；默认开市采集 60 秒，检测 SLA 配置为 75 秒。
- 推送源：认证用户专属 `/api/v1/events` SSE，携带持久游标并支持断线补发。
- 历史源：`/workspace/notifications/history`，`unread|read` 为唯一持久状态。
- 失败时显示“实时提醒已断开”，保留历史读取；不以轮询或假数据掩盖失败。

## 主操作与启用条件

“标记已读”仅在持久提醒仍为未读时可用；隐藏 Toast 只改变本地可见性。
提醒用户范围只来自当前模拟持仓、自选和最近一次服务端确认的当前标的。

## 路由与宽度

影响 `/desk`。1440px 使用既有浮层和 Toast；低于 1024px 保持同路由自适应，
不新增移动推送流程或浮动聊天入口。
