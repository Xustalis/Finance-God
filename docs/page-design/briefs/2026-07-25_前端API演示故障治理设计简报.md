# 前端 API 演示故障治理设计简报

## 用户与操作场景

已登录用户在访谈、画像与 `/desk` 中使用真实服务。交易台可能同时存在历史模拟账户；
用户需要明确区分真实接口故障与历史演示为防止未来信息泄露而主动关闭的能力。

## 页面任务与主要对象

保证前端两类 API 分别访问正确挂载点：认证、访谈、画像和语音使用 `/api/v1`，
交易台、行情、模拟交易、工作流、Agent 与提醒使用 `/api`。历史演示的主要对象是
历史行情、模拟账户与交易事实；现实资讯、现实情绪和现实研究候选不发起请求。

## 信息层级与工作区区域

顶栏、工作区布局和右侧 Agent 不变。总览的资讯/情绪区域、自选的候选区域在历史
演示中显示普通状态说明；真实 HTTP 失败继续显示风险色告警。

## 真实数据来源、频率、新鲜度与失败状态

行情和交易台数据仍由 finance API 提供，访谈与画像仍由 v1 API 提供。提醒 SSE
连接 `/api/events` 并保留游标。历史演示不读取现实资讯、情绪和候选；真实模式请求
失败时保留服务端错误，不使用演示值、静态候选或成功占位。

## 主要操作与启用条件

刷新、提醒、Agent 和交易操作合同不变。候选操作仅在现实模式且服务端返回候选时
启用；历史演示只显示信息隔离说明。

## 受影响路由与桌面宽度

影响认证/访谈/画像 API 基础设施及 `/desk`。页面视觉仅影响 `/desk`，覆盖 1440px
主画布和低于 1024px 的同路由紧凑布局。

## 视觉与交互论点

沿用纸面、墨色、风险色和现有空态样式，不引入新强调色或布局。预期不可用使用
`role="status"`，真实请求失败使用 `role="alert"`，在语义和视觉上保持一致。
