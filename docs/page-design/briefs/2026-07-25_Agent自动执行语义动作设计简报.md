# Agent 自动执行语义动作设计简报

## 用户与操作场景

已登录用户在 `/desk` 右侧 Agent 输入自然语言，例如“打开贵州茅台”或“切到交易页并帮我填买入 100 股”。用户期望左侧工作区真实响应，但最终订单提交、撤单和资金操作仍必须由用户独立完成。

## 页面任务与主要对象

补齐 `/agent/desk/decision` 到既有 `applyUiAction()` 的生产链路。主要对象是服务端校验后的语义 UI 动作批次、当前交易台上下文和前端动作回执。

## 信息层级与工作区区域

顶栏、左侧四个工作区、右侧 Agent 和浮层结构均不改。右侧继续显示 Agent 文本与错误消息；左侧只执行现有白名单动作，不新增 DOM/坐标控制入口。

## 真实数据来源、频率、新鲜度与失败状态

本改动不改变行情、账户或订单数据来源与轮询频率。动作由当前 `/desk/bootstrap` 的目录授权；服务端参数校验或上下文校验失败时保留正式 `rejected` / `stale_context` 回执并显示错误，不伪造执行成功。

## 主要操作与启用条件

Agent 可提议打开工作区、选择标的和预填仿真订单草稿等目录动作。动作只有在本次响应上下文仍等于页面当前 `context_version`、动作位于 bootstrap 目录且服务端返回 `applied` 时才改变左侧。`submit_order`、`cancel_order`、资金划转、设置和认证不进入动作目录。

## 受影响路由与桌面宽度

仅影响 `/desk` 在所有桌面宽度下的左右联动逻辑；不改变 ≥1024px 双栏或 <1024px 同路由上下布局。

## 视觉与交互论点

沿用现有纸面、墨色、朱红当前态和双线分栏，不引入新颜色、卡片或浮层。动作结果通过既有工作区状态与 Agent 错误消息表达；不增加装饰性动画。
