# API 全链路落地设计简报

## 用户与操作场景

已登录用户先在 `/app/exe` 完成画像访谈，再在 `/desk` 读取真实 PandaData 行情与
公开事实、使用模拟账户交易，并在右侧 Agent 发起直接问答或正式工作流。部署可使用
同源 `/api`，也允许 v1 与 Finance API 配置为不同根路径。

## 页面任务与主要对象

修复 API 连接、数据合同和失败语义，不改变交易台信息架构。主要对象是画像问卷
消息、行情、K 线、披露事实、融资余额事实、画像投影、Agent 流与正式工作流。

## 信息层级与工作区区域

顶栏、五个左侧标签、右侧 Agent 和浮层结构不变。总览继续展示行情、公司披露事实和
融资余额事实；失败显示显式错误。Agent 线程只有收到服务端 `done` 才完成消息。

## 真实数据来源、频率、新鲜度与失败状态

行情、K 线、披露和融资余额来自后端 PandaData adapter，并携带上游时间、频率和
freshness。浏览器不决定 K 线截断范围。请求失败保留稳定错误；最后成功行情只有在
服务端明确标记 stale 时才可展示。爬虫数据使用独立 `/crawler/*`，不覆盖市场事实
合同。mock 仅允许资讯/情绪等非交易只读参考模块显式降级，不进入价格、交易或 Agent
证据。

## 主要操作与启用条件

模拟写命令继续携带 `Idempotency-Key`；跨域预检允许该头。画像从 v1 客户端读取。
画像消息 request ID 在无安全上下文时仍必须是 RFC 4122 UUID，并在重试时复用。
Agent 流必须完整收到 `done`，超时或 EOF 提前结束均失败并保留可重试状态。

## 受影响路由与桌面宽度

影响 `/app/exe` 的画像消息请求、`/desk` 的数据与 Agent 请求，以及共享画像读取；
覆盖 1440px 主画布和低于 1024px 的同路由紧凑布局。无布局变化。

## 视觉与交互论点

沿用纸面、墨色、朱红当前态和既有错误样式，不增加颜色、卡片或布局。变化仅收紧
真实/失败/完成状态的语义。
