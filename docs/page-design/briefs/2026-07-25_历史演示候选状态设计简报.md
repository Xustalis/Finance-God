# 历史演示候选状态设计简报

## 用户与操作场景

用户在 `/desk` 的历史演示中进入「自选」，需要理解研究候选为何不可用，同时区分预期的未来信息隔离与真实服务故障。

## 页面任务与主要对象

页面继续展示自选分组与候选区域；主要对象是研究候选的可用性状态。本次修复将历史演示限制作为普通状态呈现，不再标记为读取失败。

## 信息层级与工作区区域

顶栏、工作区标签、右侧 Agent 与浮层均不改动。仅调整左侧「自选 / 可研究候选」区域的空态与错误态分流。

## 真实数据来源、频率、新鲜度与失败状态

候选仍来自 `GET /api/workspace/candidates`。历史演示不请求或展示现实候选，以避免未来信息；该边界使用 `role="status"` 的普通空态。接口真实失败继续使用风险色与 `role="alert"`。

## 主要操作与启用条件

刷新和自选分组操作不变。历史演示中不提供候选操作；现实模式中仅在服务端返回候选后提供忽略或申请交易计划操作。

## 受影响路由与桌面宽度

仅影响 `/desk`，覆盖 1440px 主画布及低于 1024px 的同路由紧凑布局。

## 视觉与交互论点

沿用现有纸面、墨色和空态样式，不引入新颜色或布局。预期限制使用普通空态，真实失败保留风险色，从语义与视觉上保持一致。
