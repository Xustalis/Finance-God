# Agent 主控交易台用户旅程原型设计简报

> 原型路径：`frontend/prototypes/journey-desk/`
> 性质：隔离交互原型，不进入生产 `/desk` 路由，不写生产 API。

## 用户与操作场景

面向有基本交易经验的个人用户与专业交易者，验证四条核心旅程：首次进入且没有交易、已有仿真持仓、收到重大行情提醒、通过自然语言让 Agent 导航或填充未提交草稿。用户设置始终由用户本人操作，不进入 Agent 上下文或动作目录。

## 页面任务与主要对象

页面任务是让用户在一个桌面工作区内完成“看事实—提出问题—观察任务—调整左侧—本人确认”的闭环。主要对象为当前工作区、当前标的、行情新鲜度、仿真账户/仓位、未提交草稿、工作流回执和提醒记录。

## 信息层级与工作区区域

- 顶栏：`FINANCE GOD` 字标，右侧仅“提醒”和“我的”。
- 左侧：横向“总览 / 持仓 / 自选 / 交易”标签；总览展示行情合同与显式失败态，其他区域展示仿真或操作结构。
- 右侧：常驻 Agent；初始化说明、已接受任务、完成态合同示例、恰好三条上下文快捷指令和输入框。
- 浮层：提醒历史与“我的”；“我的”内含设置边界说明，但不发布给 Agent。
- Agent 收起后保留可见 rail；窄屏保持同一工作区并上下排列。

## 真实数据来源、频率、新鲜度与失败状态

原型只读调用 `GET /api/market/snapshots`，不包含 PandaData 凭据，不提供演示价格回退。界面展示上游时间、实际频率与 freshness；后端未运行、无数据或响应异常时显示明确错误和刷新入口。持仓、钱包、订单全部标为“仿真结构示意”，不冒充账户事实。工作流仅展示“queued 回执”和“completed 合同示例”，不使用浏览器计时器伪造执行进度。

## 主要操作与启用条件

- 选择工作区或标的：本地 UI 状态，递增 `context_version`。
- 快捷指令：随工作区生成恰好三条；触发研究类指令只展示“需要服务端创建 WorkflowRun”的请求意图。
- Agent 控制左侧：仅执行原型动作目录中的导航、选择标的和填写未提交草稿。
- 提交/撤单/资金划转/设置：不在动作目录；出现相关自然语言时明确拒绝并引导本人操作。
- 行情刷新：仅在请求未进行时启用；失败不制造替代值。

## 受影响路由与桌面宽度

不影响生产路由。原型开发地址为独立 Vite 服务；重点验证 1440 px、1024 px 和 900 px。小于 1024 px 时保留相同内容与任务流，不创建移动版导航。

## 视觉与交互论点

**视觉论点**：一张暖米色、深墨字、细规则和双线装订的编辑部交易纸面；朱红只标当前标签与未读提醒，涨跌只用语义红绿。

**内容计划**：先给当前事实与数据状态，再给可执行工作区，最后由右侧 Agent 提供上下文任务入口；没有营销 Hero、卡片矩阵或设计说明文案。

**交互论点**：

1. 工作区/标的变化使 Agent 上下文和三条指令同步更新。
2. Agent 收起/展开采用短距离宽度过渡，工作流完成态默认折叠。
3. Agent 应用安全语义动作后，左侧目标区域短暂高亮并留下动作回执；`prefers-reduced-motion` 下取消过渡。

沿用 `--paper / --paper-light / --ink / --muted-ink / --rule / --positive / --risk`，不新增品牌色。快捷指令直接贴在输入区上方、无卡片背景、无描边和无阴影；这是对原需求“输入框上方/下方”冲突的统一裁决，遵循当前交易台规范中的“输入框上方”。
