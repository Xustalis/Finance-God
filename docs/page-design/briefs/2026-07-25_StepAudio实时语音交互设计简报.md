# StepAudio 实时语音交互设计简报

## 用户与运行场景

- 已登录用户在画像访谈或交易台右侧 Agent 中主动发起语音通话。
- 麦克风只在通话期间启用；原始音频不落盘，最终字幕沿用既有消息记录。
- 服务不可用时明确结束通话并保留文字输入，不使用浏览器语音能力静默替代。

## 页面任务与主要对象

- 主要任务：通过双向实时语音与 AI 连续交流，并能随时打断或挂断。
- 主要对象：当前 Realtime 会话、用户实时字幕、AI 实时字幕和连接状态。
- 主操作：进入语音通话；仅在已登录、当前业务上下文有效且服务端启用 Realtime 时可用。

## 信息层级与工作区

- `/app/exe`：在原访谈对话区内切换文字对话与通话状态板，不创建模态层。
- `/desk`：在共享右侧 Agent 栏内切换文字线程与通话状态板，左侧事实工作区保持挂载。
- 通话态按“连接状态—用户字幕—AI 字幕—静音/挂断”排序，朱红只用于正在收音状态。

## 数据、时效与失败状态

- 音频和字幕来自 StepFun `stepaudio-2.5-realtime` WebSocket；模型、音色和 VAD 参数由后端固定。
- 浏览器固定连接同源 `/api/v1/voice/realtime`；Vite 开发代理、前端容器 Nginx 与生产入口 Nginx 均须保留 WebSocket Upgrade。
- 字幕增量即时显示，最终字幕才合并进原消息时间线。
- 麦克风拒绝、代理握手失败、鉴权失败、上游断开、十秒连接超时和模型错误均显示明确状态及服务端错误码，并返回文字模式。
- 失败清理麦克风、AudioContext、AudioWorklet 和 WebSocket；同一页面可再次主动发起，不自动重连。
- 原始音频不缓存、不持久化；API Key 只存在于服务端。

## 受影响路由与桌面宽度

- `/app/exe`
- `/desk`
- `/admin/ai-settings`
- 以 1440px 为主画布；低于 1024px 保持同一路由和既有堆叠结构，通话状态板随所属工作区收缩。

## 视觉与交互命题

- 视觉命题：暖纸与深墨构成安静的通话台，实时状态用细规则与单一朱红强调。
- 内容计划：连接状态、双方字幕、通话控制；无营销文案和装饰性指标。
- 交互命题：进入通话时状态板短促淡入；字幕增量保持原位更新；用户打断时立即停止播放并切换收音状态，尊重 reduced-motion。
