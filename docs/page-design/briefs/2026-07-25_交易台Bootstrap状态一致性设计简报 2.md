# 交易台 Bootstrap 状态一致性设计简报

## 用户与操作场景

已认证用户打开 `/desk`、切换工作区或选择标的时，右侧 Agent 必须先取得与当前页面对象一致的服务端上下文，才能创建可审计任务。用户需要区分“正在同步”和“同步失败”，并能在失败后显式重试。

## 页面任务与主要对象

页面任务是保持当前工作区、标的、服务端 `context_version` 和 Agent 能力的一致性。主要对象为交易台 bootstrap 快照；旧快照不得在上下文变化后继续授权新任务。

## 信息层级与工作区区域

顶栏、左侧工作区和浮层不改动。右侧 Agent 在线程顶部显示 bootstrap 状态：加载中为普通状态说明，失败为错误说明并提供“重新连接”操作；成功后状态提示消失并恢复输入。

## 真实数据来源、频率、新鲜度与失败状态

上下文数据来自 `GET /api/desk/bootstrap`，在首次进入、切换工作区、切换标的和用户主动重试时读取。服务端并行装配画像投影与能力，且 bootstrap 不等待模型、不包含快捷指令。每次请求绑定发起时的工作区和标的；迟到响应不得覆盖更新后的上下文。请求失败保留真实错误，不使用本地 `context_version` 或能力兜底。

上下文 ready 后，页面以本次 `context_version` 调用 `POST /api/desk/quick-commands` 异步加载初始三条指令。快捷指令加载和失败独立呈现，不改变已同步上下文状态，不使用浏览器静态模板。

浏览器按用户保存最近一次工作区和标的，下一次进入 `/desk` 时直接以该对象发起首次
bootstrap，避免先请求默认对象再切换造成的重复服务端读取。本地值只作为请求提示；
`context_version`、能力、画像投影和动作目录不落本地，仍以本次服务端响应为唯一事实。

## 主要操作与启用条件

主要操作为提交 Agent 指令。最新 bootstrap 状态为 `ready`、`context_version` 非空且服务端确认相应 Agent 能力时即可启用；不等待快捷指令完成。Bootstrap 加载中和失败时禁用并允许重新连接；快捷指令失败时仍保留自由输入。

## 受影响路由与桌面宽度

仅影响 `/desk` 的右侧 Agent，覆盖 1440px 主画布、1024px 以上双栏和 1024px 以下同路由上下布局。

## 视觉与交互论点

沿用暖纸面、深墨、风险色和现有规则线，不引入新强调色、卡片或浮层。加载状态使用普通状态文案并通过 `aria-live` 通知；失败使用现有 `.data-error`，重试使用现有文字按钮，避免把正常等待表现成错误。
