# 复盘本地演示数据设计简报

## 用户与操作场景

开发者或评审人员通过 `/desk?preview=1` 检查交易复盘工作区，但本地测试账号尚未形成完整的模拟持仓周期。

## 页面任务与主要对象

在没有服务端交易案例时补充可切换的演示案例，覆盖已完成复盘与持仓进行中两种状态。演示内容必须与真实交易案例、成交和 Agent 结论明确区分。

## 信息层级与工作区区域

仅改动左侧“复盘”工作区：在标题下增加演示数据披露，案例表、决策时间线和复盘结果沿用现有结构。顶栏、工作区导航、右侧 Agent 与浮层不改动。

## 真实数据来源、频率、新鲜度与失败状态

正式数据仍来自 `/trade-episodes`、案例 decisions/review 与 `/agent-learning/summary`。mock 只在 `preview=1`、案例为空、请求完成且无错误时展示；真实案例优先，接口错误继续可见，不用 mock 替代失败。

## 主要操作与启用条件

用户可在两个演示案例间切换。刷新仍调用正式接口；存在真实案例后自动退出演示状态。演示案例不提供写操作。

## 受影响路由与桌面宽度

仅 `/desk?preview=1`；沿用当前 ≥1024px 双栏与 <1024px 同路由上下布局。

## 视觉与交互论点

沿用暖米纸面、墨色、规则线和现有表格，不增加强调色或卡片。演示披露使用现有空态排版，避免与朱红当前标签及双线分栏冲突。
