# 研究任务历史、取消与重试设计简报

## 用户与操作场景

交易台用户需要在同一 Agent 工作区查看跨会话研究任务、停止不再需要的执行，并在失败后复用原始输入重试或从失败节点继续。

## 页面任务与主要对象

主要对象是服务端持久化 `WorkflowRun`。历史入口先展示同栏表格，不改变当前 Agent 上下文；只有点击表格中的任务，Agent 区才切换到对应历史对话与报告。页面不以浏览器消息或 sessionStorage 作为任务事实源。

## 信息层级与工作区区域

顶部栏和左侧四个工作区不变。右侧 `AI AGENT` 标题区增加“任务历史”；历史列表、详情与当前对话在同一栏内切换。任务详情承载状态、节点、正式报告、取消和重试操作。

## 真实数据来源、频率、新鲜度与失败状态

历史、详情、取消与重试均来自 `/api/workflows`。活动 Run 延续 revision 长轮询；历史按用户游标分页并显式展示加载、空、错误和产物不可用状态。

## 主要操作与启用条件

- `queued/running` 可取消；取消处理中禁用重复提交和新任务。
- `failed/timed_out/attention_required` 可按原输入重试。
- 仅服务端确认节点产物与版本可复用时允许从失败节点继续。
- 所有写命令携带 `Idempotency-Key`，且每用户仍只允许一个活动 Run。

## 受影响路由与桌面宽度

仅 `/desk`。1440px 保持等宽双栏；小于 1024px 保持同路由上下布局，历史仍位于 Agent 区域。

## 视觉与交互论点

沿用暖纸、深墨、朱红当前态和细规则，不增加新强调色、卡片矩阵、模态抽屉或独立移动流。历史使用紧凑行表和下划线动作；状态除颜色外同时提供文字。
