# Agent 交易前端竞品与最小可运行分析

> 调研日期：2026-07-25  
> 范围：面向自主投资者的 AI 研究、组合分析与策略执行产品。只比较公开产品能力，不据营销材料推断模型质量或投资收益。

## 一、结论

Finance-God 已具备最小运行骨架：真实行情与仿真业务隔离、上下文型常驻 Agent、服务端能力探测、直答/工作流路由、持久 Run、证据包、快捷指令和白名单界面动作。当前最影响可用性的缺口不是“再加 Agent”，而是用户在委托前无法快速确认 Agent 的输入范围和权限边界。

本次选择根因修复：把已有服务端上下文、行情质量、画像投影和能力目录汇总成一张只读任务委托范围。它不新增业务事实源、不扩大交易权限，也不依赖尚未存在的会话/取消接口。

## 二、同类型产品观察

| 产品 | 公开产品闭环 | 前端启示 | 不直接照搬的部分 |
|---|---|---|---|
| Public Alpha / Agents | Alpha 嵌入资产与组合页；Agents 接收用户指令并执行周期性自主管理；平台明确实验性和用户确认责任 | Agent 必须贴着当前资产/组合对象；研究与执行责任边界需直接可见 | Finance-God 当前仅仿真交易，不应制造“代客执行”印象 |
| Composer | 自然语言生成策略，可插入结构化编辑器、修改并回测；策略结构对用户可见 | Agent 产出应落到可检查的领域对象，而不是停在聊天文本 | P0 不引入策略编辑器和回测 UI，后端合同尚未提供 |
| Magnifi | 聚合组合后回答集中度、费用、情景影响等问题，突出组合级个性化上下文 | 用户需要知道 Agent 正在使用哪些账户/组合/画像范围 | Finance-God 不接入真实券商账户，继续明确仿真状态 |
| FinChat | 传统金融终端与 Copilot 并存，强调一方 IR 内容、KPI、图表和来源 | AI 不能替代主工作区；事实、来源和人工判断应分层 | 不扩充无 PandaData 合同支持的数据集 |

## 三、差距排序

| 优先级 | 缺口 | 判断 | 本次 |
|---|---|---|---|
| P0 | 提交前上下文与权限不透明 | 会直接造成错误预期，且已有数据可完成 | 已实现 |
| P0 | 启动与失败可见 | 当前已有 Bootstrap/行情/Worker 显式错误和禁用态 | 保持 |
| P0 | 真实结果与证据 | 当前已有直答证据、工作流节点和 Evidence bundle | 保持 |
| P1 | 历史任务与结果回看 | 当前只恢复一个活动 Run；需要服务端任务列表合同，不能用浏览器本地记录充当事实源 | 待后端合同 |
| P1 | 取消、重试与人工接管 | 需要取消命令、幂等重试语义和状态机合同 | 待后端合同 |
| P1 | 结构化行动预览 | 应把 Agent 建议落为研究计划/交易计划差异，而非自由文本 | 可复用现有 TradePlan，需补合同 |
| P2 | 情景分析与回测 | 竞品的重要能力，但需要可复现数据版本、参数对象和结果合同 | 非最小运行范围 |
| P2 | 多组合/真实账户聚合 | 与当前仿真边界冲突，且涉及凭据、牌照与隐私 | 暂不进入 |

## 四、本次最小完善

在 `/desk` 右侧 Agent 增加“本次任务范围”：

- 默认一行显示当前工作区、标的和行情供应商/频率/新鲜度；
- 展开显示行情上游时间、脱敏画像投影版本、服务端上下文版本；
- 显示服务端下发的白名单界面动作数量；
- 固定说明设置/凭据隔离及订单提交、撤单、资金划转禁止项；
- 缺行情或上下文时显示不可用，不构造占位成功状态。

最小运行判定：

1. `/desk` 可构建并挂载；
2. Bootstrap 未确认能力时输入禁用并显示原因；
3. 用户提交前能核对任务对象、数据新鲜度和权限；
4. 提交后只展示服务端直答或真实工作流状态；
5. 终态产物继续按事实、推断、未知项和来源分区；
6. 真实行情与仿真交易标签不混淆。

## 五、后续边界

下一步若继续完善，应优先设计“服务端任务历史 + 取消/重试合同”，再做前端任务收件箱。不要先用 `localStorage` 保存对话或结果：这会形成第二事实源，并在跨设备、权限撤销和证据版本变化时产生不可审计状态。
